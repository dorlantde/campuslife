# 学生确认打印取件：已确认方案

- 日期：2026-10-25；状态：用户明确“采用并实现”；落实见[ADR-0040](decisions/0040-student-print-pickup.md)，实际验证见[指南](student-print-pickup.md)。
- 依据：[业务基线](decisions/0001-v1-baseline.md)、[文件引用保护 ADR-0034](decisions/0034-print-orders.md)、[商家下载 ADR-0038](decisions/0038-merchant-print-download.md)、[打印履约 ADR-0039](decisions/0039-merchant-print-fulfillment.md)。

## 1. 推荐任务与影响

新增已规划的 `POST /api/v1/orders/{orderId}/pickup`，让学生本人将待取件打印单确认为已完成，形成打印正常履约闭环。沿现有订单模块实现，不增加表、迁移、依赖或基础设施；运行操作55→56，完整规划保持62，已实现56、待开发6。

使用学生 Bearer 与规范正BIGINT字符串 orderId，无请求体；任何非空请求体（包括 JSON null、空对象）400 VALIDATION_FAILED。200 返回现有 OrderDetail，不增加客户端时间、金额、expectedVersion 或幂等键。该动作声明学生已经取件，不引入取件码、物流凭证或商家代确认。

本轮同时维护详情、列表、事件和进度枚举、注解、两份OpenAPI及Swagger/Apifox点击指南。管理员PRINT异常退款、评价、自动完成和通知另行推进。

## 2. 权限、状态与时间

仅正常STUDENT、有效会话、本人PRINT可操作。角色不符403；他人订单、不存在或BOOKING统一404。学生账号停用仍按既有规则403；重复操作也必须满足当前身份与归属。

完成旧单不要求商家账号/OWNER仍有效，也不要求当前店铺获批或营业、服务/价目上架；不反向锁商家账号或成员。这样经营资格变化不会阻断本人已取件订单的正常终结。

| 场景 | 推荐规则 |
|---|---|
| 首次前提 | PRINT、IN_SERVICE/PAID/READY_FOR_PICKUP；acceptedAt、startedAt、readyAt非空，completedAt、pickedUpAt、closedAt为空 |
| 时间 | 必要锁后固定一次毫秒now，now≥readyAt；允许同毫秒立即确认，不设置等待时长；倒退409 PRINT_TIME_INVALID |
| 原子结果 | COMPLETED/PAID/PICKED_UP；pickedUpAt=completedAt=now；订单版本+1，一条PICKUP事件，IN_SERVICE→COMPLETED，STUDENT/本人ID，reason=null |
| 其他阶段/错配 | 未付款、待接单、已接单、打印中、已关闭及不合法组合409 ORDER_STATE_CONFLICT；不代跑超时、退款或恢复已关闭订单 |

首次核对匹配的成功支付且无退款，以及文件归属学生、AVAILABLE、expiresAt=NULL的保护元数据。保留原金额、冻结规格、支付/接单/开始/待取件时间，不新增支付、退款或结算流水；模拟资金关闭也可确认。无磁盘IO、不要求再下载PDF。

已完成订单允许历史查询，不再进入普通取消/退款。原商家complete仍仅BOOKING；不授予商家代取件权限。

## 3. 重试与终态行为

本人合法COMPLETED/PAID/PICKED_UP，前序阶段时间齐全，pickedUpAt与completedAt相同，匹配支付且无退款时，重复pickup返回当前详情200。保留原完成/取件时间、版本和事件，不重复刷新文件保留期。即使文件后来过期或被清理，也能重放已保存取件事实；不重新校验首次文件保护、首次时间或版本递增条件。

推荐同步扩展商家start/ready-for-pickup：本店合法COMPLETED/PAID/PICKED_UP可返回当前完成详情200，保留原开始/待取件/取件/完成时间，不回退进度、不写事件或文件期限。仍要求当前正常商家及ACTIVE OWNER，暂停可重试；只核对完整合法阶段与支付事实，不因完成后文件清理失败。理由是响应丢失后的旧动作重试不应撤销或误报已经顺利走完的阶段。这是对ADR-0039明确留待本轮定稿的终态重试边界的推荐。

CLOSED、错配的合成完成、缺少必要时间或存在退款不作为合法重放。非法请求体在合法重放时仍400；权限无例外。

## 4. 文件保留、下载与事务

取件完成属于既有引用保护中的终结。持文件X后更新订单，再复用全部引用统计：任何关联订单未终结则expiresAt仍NULL；全部终结则按最晚closedAt/completedAt加7天设期限。仅期限实际改变才递增文件版本，重复取件不续期。

订单版本无法递增409；首次保护元数据异常，或确需变更期限但文件版本无法递增，503 FILE_STORAGE_UNAVAILABLE，整个取件回滚。若另有未终结引用、无需改期限，文件版本已到上限不阻止合法取件。学生本人下载沿原有效期规则，保留期不额外授权商家。

完成单不再是商家PDF内容授权来源；本店还有另一合格已接单/打印中/待取件关联，仍可下载该文件；只有其他店合格关联则不授予本店权限。下载互斥后新RR授权快照若在取件提交后建立，按新状态复核；若已获准传输，允许本次传输结束，下一请求重新判断。取件不等待活动下载，清理仍跳过活动传输。

沿既有学生PRINT写协议：RC账号X→会话X→店铺S→文件X→主订单X→打印明细X→事件及引用期限；不新增日期锁、商家资格锁或实例文件互斥。IO不进事务，不持业务锁等待下载。取件时间、公共状态/版本、打印进度/时间、事件、文件期限同事务，提交前复核会话；响应使用锁后视图，避免定位查询缓存混读。

同文件跨单/跨店的创建、取消、超时与取件都由文件X串行协调全部引用，不能按当前单独计算7天。双取件仅一次写入；ready与pickup的先后结果以锁后真实状态为准，pickup不得跳过待取件；下载仍普通RR读，不改成长事务行锁。

## 5. 完成标准与验证计划

1. Swagger/Apifox复现上传→报价→创建→模拟支付→商家接单→开始→待取件→学生pickup；学生/商家详情、列表及完整事件显示COMPLETED/PAID/PICKED_UP、相同完成/取件时间。正常链事件0～5，最后PICKUP。
2. 真实MySQL/HTTP验证本人权限、他人/BOOKING404、角色/停用/会话与非法请求体；未待取件不能确认。商家暂停、停用及配置变化不阻止正常学生终结旧单，资金关闭不阻止取件。
3. 验证now等于/早于readyAt、重复pickup、完成后旧start/ready重试、文件过期/清理后重放、订单/文件版本上限及保护元数据异常。
4. 注入主订单、打印明细、事件、文件期限和最终会话失效故障，核对整笔回滚；无新增资金事实。
5. 真实锁等待与双取件、待取件/取件、同文件多笔不同终结顺序及跨店引用竞争；全部终结取最晚时间+7天、重试不续期、未终结不被清理。验证无需商家账号锁、实例互斥或磁盘IO。
6. 验证完成前后本店下载权、另一合格引用、已获准传输继续与等待后新授权；回归原打印履约/取消/支付/历史与预约履约。测试只用独立临时MySQL及自有文件根。
7. 同步OpenAPI运行56/规划62/56/6、PICKED_UP与事件枚举（含既有READY_FOR_PICKUP），验证导出引用/唯一分组及可执行包启动。只记录实际执行结果。

上述权限、精确时间、终态重试与下载边界已由用户确认；实际执行结果见验收指南。
