# 打印PDF上传与本人元数据：已确认方案

- 日期：2026-10-23（Asia/Shanghai）。
- 状态：用户明确“采用并实现”。决策见[ADR-0031](decisions/0031-print-file-upload.md)，交付及实际验证见[点击指南](print-file-upload.md)。
- 依据：[业务基线](decisions/0001-v1-baseline.md)、[文件接口草案](v1-api-contract.md)、[文件元数据草案](v1-database-design.md)、[事务与清理草案](v1-state-transitions.md)。

## 1. 本轮范围

先完成学生上传文件、查看本人文件信息和未下单文件到期清理，给后续打印报价提供真实文件ID和服务端页数。

| 接口 | 本轮行为 |
|---|---|
| POST /api/v1/files | 正常STUDENT上传一个PDF，multipart/form-data字段file，成功201 FileView |
| GET /api/v1/files/{fileId} | 正常STUDENT读取本人已上传文件元数据，成功200 FileView |

本轮不开放内容下载、商家文件访问、报价或打印下单；这些在对应任务接入订单授权后开发。预计运行操作49→51，完整规划仍62，待开发13→11。新增file业务模块，按现有Controller/Service/DTO或VO/Entity/Mapper分层组织，只新增实际需要的类。

## 2. 存储与PDF解析选择

**建议先使用本机私有目录，PDFBox负责解析。** 基线中的SeaweedFS/S3只是待验证候选，尚未选定；本提案明确建议先采用本地文件系统，减少现阶段需要启动和维护的服务，集中验证文件归属、页数和生命周期。

- 开发默认目录为项目根下`.local/files/`，加入Git忽略；独立于`.cache`和`target`，不随构建或测试清理。可用配置指定绝对目录。临时文件也位于该存储根下的专用子目录。
- 存储目录不加入Web静态资源映射，不返回本地路径、存储key或公开链接。使用服务端随机key和固定后缀，原始文件名只作为展示信息，不能参与路径拼接。
- 单应用实例使用。将来改S3时需要迁移实际文件和元数据，不能只改一个配置；本轮不提前构建多后端框架。部署或备份时须同时保留数据库与存储目录，普通JAR不含上传文件。
- 建议引入Apache PDFBox 3.0.8，固定依赖版本。官方当前下载及Maven文档列出此版本：[下载](https://pdfbox.apache.org/download.cgi)、[Maven说明](https://pdfbox.apache.org/3.0/getting-started.html)。官方支持基于文件的读取；本轮使用临时文件解析，避免将整个上传再次复制为内存字节数组，参考[3.0迁移说明](https://pdfbox.apache.org/3.0/migration.html)。具体构建兼容性在实现时实际验证。

本地存储是本次需要批准的选型，不将旧候选静默当作已实现，也不将文件系统与MySQL视为一个事务。

## 3. 文件校验与上传规则

基线已有PDF及20 MB限制，本次明确按**20 MiB=20971520字节**执行，等于允许；新增建议页数**1～500页**，为校园文档场景控制单次处理规模。

- 一次仅一个file部件，不接收客户端ownerId、页数、哈希或存储位置；缺少/空文件、重复部件或额外业务字段400 VALIDATION_FAILED。只允许正常学生及有效会话；商家/管理员403，无登录或失效会话401，账号停用403。
- 原文件名取去除客户端目录后的末段，要求1～200个Unicode码点、以.pdf结尾（忽略大小写），拒绝NUL/CR/LF等控制字符；不能将名称中的路径解释为存储目录。
- 允许部件MIME为application/pdf、application/octet-stream或未声明；其他类型415 FILE_TYPE_UNSUPPORTED。名称、MIME和PDF签名均非单独可信依据，必须由解析器读取文件及页树；错误格式/解析失败422 PDF_INVALID。
- 所有加密PDF均拒绝，包括空口令可打开的加密文档；不接受上传口令。返回422 PDF_ENCRYPTED，提醒先导出无加密PDF。
- 页数超500返回422 PDF_PAGE_LIMIT_EXCEEDED；超20 MiB返回413 FILE_TOO_LARGE。HTTP multipart总请求上限留出少量封装空间，业务文件字节数仍单独校验，不能靠伪造Content-Length绕过。
- 流式落临时文件并计算实际字节数/SHA-256，解析页数；校验后保存原字节，不重新渲染或重写PDF。不将“能解析”宣称为内容净化或实际打印效果验证。
- 同时最多2个PDF解析请求，忙时429 FILE_PROCESSING_BUSY；不引入Redis限流或异步任务队列。SHA-256用于校验，不做跨用户去重。重复上传创建独立文件ID，不增加上传幂等键。

上传完成以元数据发布成功为准；长时间处理后必须再次核对账号/会话，处理中停用、退出或到期不得发布为可用文件。业务处理失败且未提交发布的上传不形成AVAILABLE；响应丢失不等于事务失败，可能已提交，重复上传仍生成新ID。

## 4. 元数据、权限与有效期

新增V11及file_asset表，19→20张业务表；不修改旧迁移，不提前创建printing_detail。保存owner_id、随机storage_key、本地存储标识、原名、实际字节数、PDF页数、SHA-256、状态、有效期、创建/更新/删除时间及版本；唯一存储key、owner索引和到期扫描索引，金额/订单表不改动。

FileView沿用规划字段：id、originalName、byteSize、mediaType（application/pdf）、pageCount、status、expiresAt。ID字符串、时间UTC；本轮成功响应status=AVAILABLE、expiresAt为发布完成时刻+24小时，不返回ownerId、哈希、磁盘位置或存储key。

GET先验证角色和归属，再判断生命周期；他人或不存在统一404 RESOURCE_NOT_FOUND，非法fileId按规范正BIGINT解析返回400。本人未过期AVAILABLE返回200；本人到期或进入删除流程/已删除返回410 FILE_EXPIRED，即使物理文件尚未清理也不能继续使用。等于expiresAt即过期。GET不续期、不启动解析或同步清理。

未来仍遵循已确认基线：未终结打印订单保护文件，全部关联订单终结后按最晚终结时间保留7天；同一有效文件可创建本人多笔订单。这些引用和7天规则在打印订单接入时落实，本轮不声称已经验证订单保护，也不开放商家或管理员读取元数据的额外权限。

## 5. 发布、补偿与清理

草案“先存文件再插元数据”在进程崩溃时可能留下无记录对象。建议增加**内部UPLOADING状态**，用于可恢复的发布占位，成功FileView不暴露该状态：

1. 文件接收、大小/签名/页树解析在数据库事务外完成。
2. 短RC事务内按账号→会话→文件顺序复核身份并创建UPLOADING占位，记录目标随机key和30分钟发布期限。
3. 事务外将已校验临时文件移入私有正式位置；再在短事务复核当前身份/占位，发布AVAILABLE并设置完成时刻+24小时。失败进入补偿删除，崩溃遗留占位可由扫描恢复。

本地同一文件的写入/清理使用实例内互斥协调，清理不能在文件发布过程中穿插删除；锁不是数据库长事务或分布式锁。文件IO、PDF解析不放在MySQL事务中。临时文件使用随机独立名称，当前请求在finally中回收；重启后遗留的临时文件由受控扫描回收，不删除正在处理的文件。

扫描启动执行一次、每60秒执行；每批最多100条，每条短事务独立提交。处理到期AVAILABLE、过期UPLOADING及上轮未完成DELETING：先锁本文件、当前读复核状态/期限，提交DELETING，再在事务外删除该记录对应对象，成功后标记DELETED；不存在视为重复删除成功，失败保留DELETING下次重试。状态/版本变更有条件更新，禁止先删磁盘再改状态。

未上传成功的占位不允许被GET视为可用（统一404），也不能供未来下单引用。DELETED保留元数据用于本人410及清理追踪，不保留文件内容；不记录原PDF正文或凭证。扫描只处理本应用创建、归属于当前配置存储根的记录及专用临时文件，拒绝路径越界、符号链接/重解析点逃逸；不递归清空存储根。

本轮验证无订单引用时的24小时生命周期。打印下单接入前必须将创建引用、终结重算有效期和清理协调接入文件锁；未完成前不能把打印创建标为可用。暂不做跨实例部署、对象存储迁移、分布式清理或整机备份系统。

## 6. 完成标准

1. Swagger / Apifox通过“选择文件”上传虚构PDF，取得201、fileId、实际页数及24小时有效期，再用GET查看本人元数据；附带可直接使用的小型PDF验收样例。内容下载暂不开放，不伪造可点击的下载URL。
2. 独立真实MySQL及临时存储目录验证PDF格式/加密/页数/大小的上下限、空部件/重复部件/未知字段、文件名和路径、不同学生隔离、角色与会话失效；201只返回服务器确认的元数据。
3. 注入文件写入/移动失败、元数据提交失败、发布前身份变化，验证无半发布文件；模拟中断后的UPLOADING/临时文件恢复，不以一次finally覆盖进程崩溃场景。
4. 验证24小时及发布期限精确边界、GET先归属后410、清理重复/并发/删除失败后重试、进程重启恢复和路径约束。单元故障注入与真实MySQL事务/并发测试分别记录，不凭mock声称锁正确。
5. 新增错误响应、Swagger上传表单、springdoc模块扫描、运行及完整OpenAPI、ADR、存储目录说明和人工点击指南；预期51个可调用操作，以实际导出为准。
6. 不访问用户现有项目库或现有文件，自动测试全部使用独立实例和自有临时目录；只按记录验证清理，不执行存储根清空。实际测试/构建/启动结果在交付时记录，当前尚未执行本方案验证。

本地私有存储与PDFBox选型、500页和解析并发上限、上传/本人元数据范围、发布与24小时清理细则已获确认。下载、报价、订单引用与商家文件授权随后独立定稿。
