# 公开评价与真实商家评分统计：已确认方案

- 日期：2026-10-26；状态：用户明确“采用并实现”；落实见[ADR-0043](decisions/0043-public-shop-reviews.md)，实际验证见[指南](public-shop-reviews.md)。
- 依据：[公开目录 ADR-0019](decisions/0019-public-shop-catalog.md)、[学生评价 ADR-0042](decisions/0042-student-order-review.md)、[接口草案](v1-api-contract.md)、[数据库设计](v1-database-design.md)。草案中的公开展示细节仍需本次定稿。

## 1. 推荐范围与完成标准

新增规划中的GET `/api/v1/shops/{shopId}/reviews`匿名分页入口；同步把既有公开商家列表GET `/shops`、详情GET `/shops/{shopId}`的rating/reviewCount从阶段占位值改为真实公开评价统计。

本轮运行58→59个操作，完整规划仍62，已实现59、待开发3。复用V13 order_review及现有账号/店铺表和评价索引，仍V1～V13、22张业务表；无新迁移、缓存、消息、搜索服务或冗余评分字段。公开接口放merchant内现有Controller/只读服务及实际需要的查询Mapper/VO，评价事实仍由order模块写入，不改变已有评价写协议。

完成标准：匿名能看可见店铺的公开评价；公开列表/详情显示真实可见评价数及平均分；隐藏/新增/昵称变更在后续快照正确反映；同一响应的数据来自同一只读快照，批量统计不逐店查询；注解、两份OpenAPI和Swagger/Apifox点击指南同步。

本轮不增加管理员隐藏动作、商家回复、评价编辑/删除、匿名开关、图片、敏感词/自动审核、评分排序/筛选或管理员账号管理。HIDDEN过滤及保留事实可测试，不代表已有隐藏接口。

## 2. 店铺可见性与匿名边界

沿ADR-0019：只有APPROVED、ACTIVE OWNER及ACTIVE/MERCHANT经营账号的店铺公开可见。停业、当前休息、无上架服务或分类字典停用不隐藏；暂停/未批准/经营资格失效店铺与不存在统一404 RESOURCE_NOT_FOUND，不能通过评价入口绕过目录资格。

评价分页只精确匿名放行GET `/shops/{shopId}/reviews`，保持既有匿名接口行为：不带token可读；主动携带无效/撤销/过期token或停用账号凭据仍按原鉴权错误拒绝，不自动忽略错误凭据。不会放行其他方法、本人评价或管理员路径。

shopId沿公开目录的规范正BIGINT字符串解析（不接受前导零、符号、空白或溢出）。参数格式错误400，合法参数但店铺不可见404；先完成参数格式校验再判断可见性。隐藏店铺不会返回“空评价页”而泄露其存在。

## 3. 公开分页、内容和昵称

仅返回该店铺visibility=VISIBLE的全部历史评价，包含BOOKING和PRINT，按createdAt DESC、id DESC稳定倒序。不增加评分/业务类型/关键词筛选，不能传学生或订单ID切换查询范围。

page默认1、正整数至INT最大；size默认20、1～100，显式空串/负数/小数/非数字/溢出400。沿公开目录现有十进制分页解析，offset用long；越界页items=[]，保留真实total/totalPages。响应PublicReviewPage：items、page、size、total、totalPages，无额外平均分副本，评分统计读取商家列表/详情。

每条PublicReviewView严格五字段：reviewId字符串、rating整数1～5、原content、reviewerNickname、createdAt（UTC）。不返回studentId、orderId、登录名、联系方式、visibility、审核原因、存储信息或完整账号对象。文字保持原评价内容，不当富文本解释，不增添自动脱敏规则。

推荐reviewerNickname读取作者当前账号昵称，不新增昵称快照列；修改昵称后，后续请求中的历史评价一起显示新昵称。理由是继续使用现有本人昵称修改规则并避免另一套身份快照；本次已确认这项展示行为。

推荐作者账号停用或之后角色变化不自动隐藏既有VISIBLE评价，也不扣除统计；公开评价资格由保存的visibility决定，账号停用负责登录/操作权限，内容下架由独立隐藏规则处理。学生自身无法登录时仍不能本人读写。昵称关联只读取昵称，不以当前学生账号状态/角色过滤评价；不重新核验原订单/服务/人员的当前资格。

HIDDEN不出现在公开分页、total或平均分中；本人GET仍可读HIDDEN，订单reviewed仍true，一单唯一规则不变。下一项管理员隐藏接入后沿同一过滤规则生效。

## 4. 真实评分口径与精度

公开ShopSummary/ShopDetail保留现有rating与reviewCount字段和JSON数值类型，只替换真实数据来源：

- reviewCount为该店铺全部VISIBLE评价数，包含两类业务，与公开评价分页total同一口径，不只统计当前页。
- count=0时rating=null、reviewCount=0，表示确实没有公开评价，不补虚构5分。
- count>0时rating=SUM(rating)/COUNT(*)，用十进制计算、保留两位小数、HALF_UP四舍五入；不使用浮点逐条累加，不先对各页或业务类型分别平均。
- JSON数值不承诺补齐末尾零，例如4或4.0与4.00数值等价；前端若需固定两位自行格式化。评分范围仍1～5。

示例：评分5、4、4，共3条，rating=4.33/reviewCount=3；5、5、4则4.67。隐藏其中一条后按剩余记录重算，全部隐藏回null/0。四舍五入临界示例：1分7条和2分1条，均分1.125→1.13。

只计算真实VISIBLE评价，不按作者是否启用、昵称是否变化、服务是否下架、文件是否清理额外增减。店铺本身不可见则整个公开资源404或列表排除，不展示其统计。商家后台资料接口本轮不新增评分字段。

## 5. 查询、快照与取舍

三个公开响应沿现有短只读RR：

1. 评价页同一快照读取店铺可见资格、可见评价total、页内记录及作者昵称；普通读，不取业务行锁。
2. 商家列表同一快照完成目录资格/count/page、营业时间及当前页店铺的评价聚合。按页内shopId批量GROUP BY查询，空页不查评分，不逐店加载全部评价或逐店单查。
3. 商家详情同一快照读取资格、营业时间及该店聚合；只有可见后才返回评分。

不写冗余平均分、不更新店铺/订单/账号/文件版本，不动事件、资金、占用、文件期限或评价内容；无需写事务、日期保护行、文件X或实例文件互斥，无磁盘IO。使用既有(shop_id,visibility,created_at,id)索引及精确过滤，不引入分页插件。

快照建立后并发新增评价、隐藏、昵称修改或停用成员/经营账号，不改变本次已建立快照；下一请求按新快照重判。只保证单个响应内部一致，不保证不同HTTP请求、不同页一直处于同一时刻；分页期间新增记录可能移动后续页，这是普通页码分页的边界，本轮不增加游标或持久快照。

SUM使用能承载精确整数和的十进制结果、COUNT使用long，分页偏移用long；转换输出前才做两位小数计算，避免整数除法截断。数据库暂时竞争/连接问题沿项目错误处理，不用静默null/0掩盖读取失败。

## 6. 验收范围（实际执行记录见指南）

1. Swagger/Apifox实际完成预约/打印并评价；不带token查询公开评价、商家列表/详情，核对五字段、真实count/平均分与零条null/0。文档不再描述统计阶段值。
2. 公开资格、停业/休息/无服务/分类停用、不可见统一404；精确匿名路径/方法，无效token仍拒绝。shopId及分页边界、超大页offset、同毫秒id倒序、多页/越界页均覆盖。
3. 真实VISIBLE/HIDDEN混合、全隐藏、跨店、多业务及不同评分；验证4.33/4.67/1.125→1.13与评分范围，分页total和统计都不受页大小影响。人工构造HIDDEN仅验证读取规则，不宣称隐藏动作已实现。
4. 昵称修改后历史展示新昵称；作者停用/角色变化后记录和统计保留；公开响应没有学生/订单ID、登录名、审核原因等字段，本人读取和一单一评保持。
5. 真实MySQL并发插入/隐藏/昵称修改/经营资格变化期间，同响应资格、total/items/统计维持RR快照，下一请求变化；读不阻塞合法评价写入，不获取业务写锁或实例互斥。
6. 多店页内批量聚合、空页不查询、既有目录搜索/分页/openNow与学生评价/详情reviewed/文件清理回归；不声称未经测量的性能提升。
7. 无新迁移，仍V1～V13/22表；运行59/完整62/59/3、注解、两份OpenAPI、模型/引用/唯一分组及可执行包启动检查；只用独立临时MySQL和自有文件根，完成后记录实际结果与点击指南。

本次已确认当前昵称动态展示、停用作者不自动隐藏、两位小数口径、分页及RR边界。已确认范围按ADR-0043落实，实际执行结果仅以验收指南为准。
