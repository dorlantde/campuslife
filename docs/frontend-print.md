# M05.2批次C：打印整链页面使用指南

2026-10-29，依[ADR-0049](decisions/0049-minimal-frontend.md)接入既有V1业务。打印主流程及退款/权限分支已在真实浏览器和临时MySQL验收；[报告](reports/frontend-batch-c-2026-10-29.md)区分自动测试、实际点击和未完成的窄屏复核。预约及管理员异常/其余管理页面留到D，不新增业务规则。

## 启动与入口

按原VS Code配置启动后端，在仓库根终端运行：

```powershell
.\scripts\frontend.ps1 -Action Run
```

打开 **http://127.0.0.1:5173**。工具首次准备见[运行指南](frontend.md)。后端的数据库、JWT及模拟资金开关仍由原配置决定，不填进前端；普通构建不会把前端dist打入后端jar。

| 身份 | 页面入口 | 当前范围 |
|---|---|---|
| 学生 | 商家详情的“选择PDF打印” | `/shops/:shopId/print/:serviceId`，上传/读取本人PDF、下载、报价和下单 |
| 学生 | 顶栏或工作区“我的订单” | `/orders`和`/orders/:orderId`，列表、冻结详情/事件、模拟付款、允许取消、取件和本人评价 |
| 商家 | 顶栏“订单任务”或工作区卡片 | `/merchant/orders`和`/merchant/orders/:orderId`，本店列表/详情/事件、接拒单、未开始取消、任务下载、开始打印、待取件 |

批次D已把列表扩展为两类，打印流程可筛选PRINT；预约使用自己的动作，最新入口名为“我的订单”和“订单任务”，见[预约与管理指南](frontend-booking-admin.md)。所有ID与版本保留字符串，金额以整数分传输、元展示，时间标明上海校园时间。没有本人文件列表接口，可输入已知本人文件ID；页面不虚构文件库。

## 一条完整点击流程

1. 商家完成[入驻与配置](frontend-merchant.md)：获批准、有效店主、打印服务已上架、目标规格启用，设置营业时间并开启营业。营业中不保证所有下单条件成立。
2. 学生登录，在该商家服务卡点“选择PDF打印”。选择PDF并点“上传PDF”，核对服务器返回的文件ID、名称、页数及期限。也可输入本人有效文件编号，点“读取本人文件”。改变编号后必须重读；选新文件后旧报价失效。
3. 选择A4黑白/彩色、单面/双面和1～100份，点“获取打印报价”。例如5页双面两份按每份3张，合计6张纸；单价按印刷面计，不由页面把双面自动半价。
4. 核对真实规格版本、应付金额和备注，点“确认创建待支付订单”。成功显示编号，再点“查看订单”。15分钟待支付期限以服务器事实为准，页面不会倒计时归零就宣称关单。
5. 点“模拟支付”，核对冻结金额后确认。它不涉及真实资金。原模拟开关关闭时如实显示503，页面不能自动启用；已发生的支付/退款事实仍按后端返回展示。
6. 在独立商家标签页登录同店账号，进入“订单任务”，按状态筛选并查看订单，点“接单”再确认。接单前没有任务下载入口；接单后“下载任务PDF”通过带身份的请求获取附件。
7. 商家核对内容后“开始打印”，然后“标记待取件”，均需确认。开始后不再提供普通取消，没有商家“完成打印订单”按钮。
8. 学生刷新详情和事件，核对待取件后点“确认已取件”，再“确认取件”。完成后可提交1～5分及文字，一单一次；页面显示已保存评价及可见性。公开商家详情随后显示真实评价和评分。

学生和商家各用一个手动新开的独立标签页；复制标签页可能复制初始会话，操作前核对顶栏身份。管理员不默认拥有PDF内容权限。本批无需复制token或手写HTTP请求。

## 结果不确定与改价

下单前把当前账号、CREATE_PRINT操作、随机幂等键及原正文保存到**本标签页sessionStorage**，不保存PDF或密码。存储不可用则不发起新单。此记录只覆盖当前标签页生命周期，不是跨设备恢复服务。

- 网络中断/超时/不确定响应后保留记录并禁止用新草稿直接下另一单。刷新页面仍可点“核对原提交（原键重放）”，发送原键和原正文；不会自动重试、自动换键或使用改过的表单。
- 已确认记录也可用原键核对，服务端返回原订单。需要另一单时先核对订单列表，再明确“核对后清除恢复记录”；清除记录不取消服务端订单。
- `QUOTE_CHANGED`后只复制原六项规格重新查询报价，展示原/新金额与规格版本；旧提交保持被拒绝状态。清除旧记录、核对新报价后才能明确创建新单，不自动接受涨价。
- 退出或改密前，如有未确认/被拒绝的记录会先提示。明确退出、认证失效或切换账号时清除恢复数据；重新登录不会自动重放旧提交。账号切换的旧响应也不能写进新页面。

没有向正常运行环境加入“制造断网”按钮。上传本身没有创建幂等：上传响应丢失时提示可能已保存，不自动重复上传，未引用上传按原24小时规则清理。

## 取消、下载与错误反馈

| 情况 | 页面与预期 |
|---|---|
| 学生未付取消 | 关闭/未支付/打印终止，无新支付或退款 |
| 学生已付待接单取消 | 全额模拟退款；商家已接单后学生不能普通取消 |
| 商家待接单拒单 | 填1～300字符原因后确认，全额模拟退款、保存原原因 |
| 商家已接未开始取消 | 通过“无法履约取消并退款”，开始后无此普通入口 |
| 服务端冲突 | 保留原错误code/trace并尝试重读订单/事件。支付/接单到期的409可能已经先提交关闭或退款，需看实际状态 |
| 刷新失败 | 保留旧显示供核对，但禁用业务动作，直到详情/事件重新读取成功 |
| 文件权限 | 商家仅凭当前合格任务下载；保留7天不等于商家仍能下载。完成后本人仍可按保留期下载；已有别的合格任务可能继续授予本店权限 |
| 下载失败 | JSON错误、非PDF、空响应或206不保存为文件；认证失效清会话。token不进URL，附件名安全处理，临时对象URL释放 |

所有打印引用结束后，文件按最后终结时间保留7天；有任一未结束引用时显示“关联订单保护中”。GET不延长文件期限，页面不访问内部存储路径。

## 开发验证与隔离复现

```powershell
.\scripts\frontend.ps1 -Action Test
.\scripts\frontend.ps1 -Action Build

# 可选：只启动一次性隔离环境，不能同时占用5173
.\scripts\preview-frontend.ps1 -Action Start
# 验收后结束；等待Status显示数据库清理完成
.\scripts\preview-frontend.ps1 -Action Stop
.\scripts\preview-frontend.ps1 -Action Status
```

隔离环境原三角色账号见[运行指南](frontend.md)；本批另提供`baseline_owner_5`作为已批准打印店店主、`ui_other_m052c`作为另一学生，均使用公开虚构密码`Ui_Test_2026!`。它们只在随机临时MySQL中存在。预置商家1000005、四规格和全天时段仅为测试准备；原项目库不创建这些账号或配置。模拟资金只在该显式测试夹具中开启，自动过期扫描/评分缓存关闭；缓存验证仍走M02专用流程。

需要复现提交成功后响应丢失时，使用`preview-frontend.ps1 -Action Start -DropFirstPrintResponse`。Vite仅在核对当前临时库、证据目录和随机后端端口一致后，对首笔成功打印创建读取后端结果、保存订单ID/原键证据并断开响应；重试原键正常转发。普通Run/Build默认不启用，不改后端或浏览器安全设置，不记录密码/Authorization。
