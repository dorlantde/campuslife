# 管理员停用与恢复账号：已确认方案

- 日期：2026-10-26；状态：用户明确“采用并实现”；落实见[ADR-0046](decisions/0046-admin-account-status.md)，实际验证见[指南](admin-account-status.md)。
- 依据：[账号列表 ADR-0045](decisions/0045-admin-account-list.md)、[接口契约](v1-api-contract.md)、既有账号版本、会话撤销与订单权限规则。以下自操作、并发、重试和操作记录细则已由用户本次确认。

## 1. 推荐范围

新增已规划的PATCH `/api/v1/admin/accounts/{accountId}/status`。正常ADMIN使用有效会话，管理其他STUDENT、MERCHANT或ADMIN账号，目标状态仅ACTIVE或DISABLED。复用AccountView返回六项资料，不改变用户名、昵称、密码、角色或账号归属。

请求严格只有status和expectedVersion，成功200。例如：

```json
{"status":"DISABLED","expectedVersion":"3"}
```

accountId须规范正BIGINT字符串；expectedVersion须规范非负BIGINT字符串，0允许，禁止前导零、空白、符号、小数和溢出。status须精确大写字符串；null、漏字段、错误类型或额外字段400 VALIDATION_FAILED。

推荐本轮同时保存状态变更历史：V15新增account_status_change表，仍由admin模块维护，无新增基础设施。运行61→62，完整规划62/62/0，V1～V15、23张业务表。接口目录全部实现表示当前规划入口齐全，不代表部署、前端、性能或全部后续业务已经完成。

不提供账号删除、修改角色、重置密码、批量修改、解除指定设备会话或状态历史查询HTTP入口；ADMIN仍只通过受控初始化创建。

## 2. 管理员自操作与最后一个有效管理员

推荐禁止修改本人状态，包括请求状态已一致的情况：409 ADMIN_SELF_MODIFICATION_FORBIDDEN，无任何写入。需要停用管理员时，由另一名正常ADMIN操作；可以停用或恢复其他ADMIN。

保护最后有效管理员无需新增计数表或全局锁：每次成功操作必须在数据库锁内确认操作者仍为ACTIVE/ADMIN，且目标不是本人，并将操作者账号锁持有至提交。这样每次停用其他ADMIN时，至少保留操作者这一名有效管理员。

两名管理员互相停用时，双方账号按同一顺序加锁；先成功提交者保留有效身份，后一个取得锁后发现自身已停用，403 ACCOUNT_DISABLED，不再停用对方。多名管理员交叉操作同样依锁后当前身份决定，不能只靠事务外COUNT或token中的旧角色保证存量管理员。

此保护适用于项目受控创建和HTTP状态操作；直接在数据库修改角色/状态不属于该协议，不能据此保证绕过应用后的管理员数量。

## 3. 版本、重复请求与原子提交

先校验当前管理员和会话，再核对目标存在、本人限制和expectedVersion。目标不存在404 RESOURCE_NOT_FOUND；目标版本不匹配409 CONFIG_VERSION_CONFLICT，任何目标状态下均不绕过版本检查。

- 版本匹配、状态确实改变：目标账号version+1，撤销目标全部尚未撤销的会话，追加一条状态变更记录，与状态更新同事务提交。
- 版本匹配、状态已经一致：200返回当前AccountView，不递增版本、不撤销会话、不追加记录。达到Long最大版本时也可执行这个无变化请求。
- 需要实际改变但版本已经Long最大：409 CONFIG_VERSION_CONFLICT，无写入，避免溢出。
- 首次成功后原版本重试：409，先刷新账号列表确认当前状态/版本；刷新后提交一致状态可200无写入。不用旧版本覆盖期间其他管理员的停用/恢复或本人资料变化。

状态、版本、会话撤销或记录写入任一失败，整笔回滚；撤销零条会话是合法结果，不能当作失败。锁等待后及写后提交前复核操作者会话期限，到期/撤销拒绝并回滚。数据库暂时故障503，其他内部错误500，不伪造成功。

## 4. 会话与恢复

推荐停用和恢复这两种实际状态变更都撤销目标全部未撤销会话，包含多设备及已过期但尚未标记撤销的记录；使用现有撤销时间不早于会话创建时间的规则，不删除历史会话或修改其到期时间。

停用后拒绝新登录及后续鉴权访问。恢复只恢复账号启用资格，不自动登录、不复活旧token；即使旧DISABLED样本来自历史管理操作、仍残留未撤销会话，恢复时也一并撤销，必须重新登录。

账号锁与登录创建会话协调：先创建并提交的会话会被随后状态变更撤销；状态变更先提交时，后续登录按锁后当前状态判断，DISABLED拒绝，ACTIVE才可建立新的会话。

已有只读RR快照或已经获准的文件传输继续沿原边界：停用不强制打断本次已授权响应/下载，下一请求重新鉴权。正在写入的业务若先持有目标本人账号锁，可以先完成；停用在其后提交。其他账号发起、已经完成经营资格复核的在途业务继续沿各模块原授权时点处理，停用提交后的新资格读取看到失效；本轮不增加跨全部业务的全局中断机制。

## 5. 存量业务与公开展示

停用不自动取消、退款或完成任何订单，不释放预约资源、不更改打印文件期限，不删除文件、评价、店铺、服务或成员关系；恢复也不重写这些业务配置。

沿现有规则产生的结果：

- 学生停用后本人新请求拒绝，商家仍可处理本店既有任务，正常ADMIN仍可核实已付未终结异常；自动超时扫描沿原期限和模拟资金开关工作。已完成订单不因此获得退款资格。
- 商家经营账号停用后，后续新快照中的公开店铺因既有可见资格失效而隐藏，按新资格判断的学生下单/首次付款请求拒绝，商家本人不能登录处理订单；已付存量占用和文件保护保留。需要处理时，由其他正常ADMIN按既有异常入口核实，或恢复商家后重新登录处理；本入口不自动发起资金操作，在途资格复核边界沿上一节说明。
- 恢复商家后，公开可见与接单资格按原店铺/OWNER/配置条件重新计算；店铺原本暂停、未批准或成员无效时，不因账号恢复而自动获批或激活。
- 作者停用不自动隐藏既有VISIBLE评价；本人无法访问时，其公开评价及评分仍按ADR-0043/0044规则处理，隐藏须独立管理员操作。
- 已完成/关闭打印订单的保留期及未终结引用保护沿原规则，不因账号状态变化重新计时。

本轮不新增批量善后、换店主、代取件、完成后退款或资金开关绕过规则。

## 6. 锁协议与变更记录

推荐写事务RC：

1. 将操作者和目标账号ID排序，按ID升序逐条主键点查FOR UPDATE；去重，不靠单条IN或排序结果假定数据库锁定顺序。
2. 从锁后账号行复核操作者ACTIVE/ADMIN，再锁其当前会话并校验；判断目标、本人限制、版本和状态。
3. 实际变更时更新目标状态/版本，撤销目标会话，插入变更记录；返回锁后当前六字段，提交前再次校验操作者会话期限。

所有账号锁都在任何会话锁之前取得。本路径需要两个账号锁；既有业务的本人账号→本人会话→店铺/日期/文件等锁序保持，本路径不取这些业务资源锁，也不在取得会话锁后追加账号锁。排序可避免管理员交叉管理造成账号反向等待；须以真实MySQL验证，不以mock宣称正确。

account_status_change推荐字段：id、actor_account_id、target_account_id、from_status、to_status、from_version、to_version、changed_at（锁后UTC毫秒时刻）。操作者/目标FK account，两个状态须合法且不同、两个版本非负且相差1；UNIQUE(target_account_id,to_version)防止同一次状态版本重复记录。

仅实际状态改变追加，不改写旧记录；账号其他资料变化可以造成记录间版本跳号，不把这误判为状态历史丢失。本轮记录谁、何时、对谁做了哪次状态/版本变化，正文仍只需status和expectedVersion，不增加原因字段或对外查询路径。既有账号从V15启用后开始记录，不虚构历史处理人。

## 7. 验收标准

1. Swagger/Apifox从账号列表取得目标ID/version，停用学生/商家/其他管理员；核对200新状态、版本+1、旧token拒绝、新登录拒绝。用最新版本恢复，再验证必须重新登录、旧token仍失效。
2. 本人任意状态请求409；唯一ADMIN不能停用自己；两个及多个管理员交叉停用，真实并发仍留至少一个ACTIVE/ADMIN，等待后已失效操作者不能继续写入。禁止公开创建管理员或改角色。
3. 规范ID/状态/版本和严格JSON；未知目标404，旧版本409、MAX版本实际变更409及一致状态200；重试不重复增版本/记录，响应丢失后可通过列表确认。
4. 多设备撤销、零会话、历史未撤销DISABLED样本恢复、并发登录/改名/改密/退出；账号状态与版本、全部会话撤销、单条历史记录原子一致，失败或提交前过期全部回滚。
5. 订单/资金/预约占用/文件期限/成员和评价事实保持；现有公开资格、商家处理旧单、管理员异常、超时扫描、已获准传输及RR快照边界回归。新资金仍遵循模拟开关。
6. V15迁移及历史记录约束、运行62/完整62/62/0、注解/两份OpenAPI/点击指南、既有认证/资料/管理员功能及可执行包启动检查。只使用独立临时MySQL和测试自有文件根，不修改用户现有服务数据或启动密钥。
