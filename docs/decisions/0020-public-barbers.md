# ADR-0020：公开理发师查询

- 日期：2026-10-21（Asia/Shanghai）。
- 状态：用户对[公开理发师提案](../public-barbers-design.md)明确选择“采用并实现”。
- 范围：一个 GET /api/v1/shops/{shopId}/barbers，人工与实际验证结果见[验收指南](../public-barbers.md)。

## 规则

店铺可见资格、停业/分类字典停用仍展示、匿名及无效凭证处理沿用 ADR-0019。仅本店已启用且至少关联一项本店已上架 HAIRCUT 服务的人员可公开；空绑定、仅下架绑定和停用人员不返回。无营业时间或排班不隐藏人员；本接口不表示可预约。

shopId、serviceId 使用规范正 BIGINT 字符串，非法/显式空值为 400；省略 serviceId 才是不筛选。传入时要求店铺为 HAIRCUT、目标为本店已上架 HAIRCUT 服务，不存在、跨店、下架或非理发统一 404；合法服务无人绑定返回 []。可见 PRINT 店铺不传筛选返回 []，传入任意合法服务 ID 返回 404。不可见店铺始终 404。

只返回 PublicBarberView：id、displayName、serviceIds，不返回人员版本、启停、归属内部信息或排班。人员按 created_at DESC、id DESC，不合并同名人员；serviceIds 为全部本店上架理发服务的数值升序字符串 ID。按 serviceId 筛选只改变人员集合，不截断其 serviceIds。沿用数组，不增加分页。

## 实现与取舍

继续在 merchant 公开目录中实现，复用统一店铺资格和只读 RR 事务。一次请求中的店铺、筛选服务、人员和绑定来自同一快照；不写配置或递增版本，下一请求看到已提交的新状态。仅精确匿名放行新增 GET，不提前开放预约/评价、其他方法或子路径。

PublicBarberMapper 联表读取启用人员及全部有效绑定；显式限定服务和人员同店、服务 HAIRCUT 且上架，独立外键不能替代这些条件。使用 EXISTS 按目标绑定筛选人员，避免将联表服务列也限制为目标服务而丢掉其余公开 ID。结果按人员 ID 分组，不按姓名合并，不逐人员查服务。

跨店/错误类型关系即使通过直接 SQL 人为建立，也不能公开；查询忽略无效关系，不自动修复或修改原数据。PRINT 店铺在业务入口返回空结果或不可见筛选资源，不能因存在人工异常人员而公开。

无新依赖、XML、表或迁移，仍复用 V1～V8 十三张表。预约创建与可约查询仍须分别实现，届时在统一锁协议下复核服务、人员、排班与占用；本轮查询测试不能替代预约并发验证。
