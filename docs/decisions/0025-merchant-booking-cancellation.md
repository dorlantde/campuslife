# ADR-0025：商家已接单预约无法履约取消

- 日期：2026-10-22。
- 状态：用户已明确“采用并实现”。细则见[已确认方案](../merchant-booking-cancellation-design.md)，人工验收见[取消指南](../merchant-booking-cancellation.md)。

## 决定与理由

新增POST /merchant/orders/{orderId}/cancel，正常商家及本店ACTIVE OWNER可在无法履约时取消已接单BOOKING并全额模拟退款。处理存量责任无需店铺当前仍APPROVED，暂停/停业/下架不改变原快照；账号或OWNER停用仍禁止操作。

把基线“开始前”精确定为锁后服务器now严格早于预约startAt；等于或超过开始时刻，即使仍ACCEPTED也409 CANCEL_WINDOW_CLOSED，无写入。避免漏点开始后继续使用普通取消。商家不受学生1小时窗口限制，可在开始前最后1小时承担无法履约责任；已接单不重新判断原30分钟接单期限。

请求只有reason，去首尾空白1～300个Unicode码点；沿用严格格式与未知字段拒绝。成功写MERCHANT_UNAVAILABLE及closeNote，全额退款reason/reason_note记录责任，ACTIVE释放，version+1、一条MERCHANT关闭事件，保留原支付及acceptedAt。退款、关闭、释放、事件同事务提交。

同原因已成功关闭重放200，不改时间/版本/流水，重放不重新判断首次取消窗口或资金开关；不同原因或其他关闭原因409，不覆盖历史责任。首次状态与时间验证先于资金开关，新退款受默认关闭的开关保护，503无副作用。复用现有唯一退款约束与服务器版本条件，无新增客户端幂等键。

## 锁与实现边界

写RC，账号→会话→店铺S→OWNER复核→日期保护行→订单/预约当前读→退款/状态/事件，提交前复查会话。商家接单/拒单/取消共用同一私有锁入口，等待前定位快照不能作为最终状态。失败整笔回滚；真实锁竞争503，重试重新验证状态与时间。窗口已过为不写入错误，不套用待接单到期的“先退款关闭再409”。

新增一个严格原因DTO，复用已有Controller/Service/事务及关闭SQL；V1～V10仍19张业务表，无新迁移、XML、依赖或基础设施。运行41个操作，完整62个、21个待开发。

开始/完成、管理员异常、打印取消及商家列表/事件仍待后续任务；到预约开始后的未开始异常不自动退款或判定未到店。合成IN_SERVICE测试仅检查状态边界，不代表开始接口已交付。实际验证范围见取消指南。
