# ADR-0022：待支付预约、真实占用与释放

- 日期：2026-10-22（Asia/Shanghai）。
- 状态：用户对[完整方案](../booking-order-design.md)明确选择“采用并实现”。实际执行结果见[验收指南](../booking-orders.md)。
- 范围：创建待支付预约、本人详情、未支付取消三个接口，真实占用过滤、未支付超时关闭及相关配置保护。支付、商家履约、打印、退款及评价继续分步开发。

## 决定与取舍

采用 service_order + booking_detail 的主/扩展结构，另建 order_event、idempotency_record；V9 共四张表，当前十七张业务表。占用状态就在预约扩展中，避免重复维护。正常流程本轮仅 PENDING_PAYMENT / NOT_PAID / HELD，关闭为 CLOSED / NOT_PAID / RELEASED，不生成支付或退款事实。

输入和资格、时间、报价、快照、幂等、保护规则完整沿用已确认方案。金额为整数分，服务版本与预期金额不匹配为 QUOTE_CHANGED；同键、同归一化请求返回原单，关闭后也不重建。重放仍鉴权，不要求旧服务配置仍可售。时间采用规范 Instant，备注归一，摘要包含所有报价字段。

写事务 RC，身份按账号 → 会话协调。交易先店铺 S，再日期保护行 X，再受保护配置与订单。配置店铺 X → 人员/日期升序保护行 → 后续资源。店铺锁内不反向锁经营账号。订单归属、人员/日期等定位值锁后重新检查；已有配置在店铺 S 内保持稳定，同一日期占用以锁内当前读复核。不同日期/人员允许并行，配置与同店交易互斥，这是以简单性换取可解释正确性的选择。

创建、关闭和幂等记录原子提交；首次创建事件为序号 0，关闭事件与订单新版本一致。唯一键竞争整笔回滚后新事务读原结果；死锁/锁超时整笔回滚返回 503，不从失败 SQL 中间继续。

未支付期限为创建时间 +15 分钟，now >= deadline 即到期。取消发现到期时，事务先提交 PAYMENT_TIMEOUT 关闭与释放，外层再转换为 409，避免异常撤销已完成关闭。每 30 秒最多扫描 100 个到期 ID，每单独立事务；启动立即首扫，重复或多实例扫描按状态收敛。失败保留数据库事实供下次重试，不引入 Redis/MQ。测试可关闭自动触发以控制 Clock，但直接验证相同扫描与事务方法；生产默认启用。

公开候选从原“仅配置与排班”升级为排除 HELD / ACTIVE / CONSUMED 的真实占用；未提交关闭的过期 HELD 仍保守占用。候选仍不预留资源，创建锁内重新校验。

手动停业、服务下架和名称/价格/时长修改不自动关闭原订单，原快照保留。停用人员或删除绑定保护未结束 HELD/ACTIVE；修改排班/营业时间还须覆盖未结束 CONSUMED 的原区间。先处理预约再变更，冲突不写入、不增加配置版本。历史已结束区间不永久阻止未来配置。

## 验证边界

采用真实 MySQL 验证重叠竞争、幂等、取消/超时与创建、配置修改与创建、锁等待后期限/会话复核和失败回滚。纯时间/摘要规则另作单元验证；不把 mock 或格式检查当作锁正确性的证据。执行数量和结果仅在验收指南记录，未实现支付/履约不宣称相应测试已经通过。
