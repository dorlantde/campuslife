# ADR-0026：预约开始与完成履约

- 日期：2026-10-22。
- 状态：用户已明确“采用并实现”。细则见[确认方案](../merchant-booking-fulfillment-design.md)，验收见[履约指南](../merchant-booking-fulfillment.md)。

## 决定与理由

新增本店BOOKING开始/完成两个无请求体接口，补齐正常预约生命周期。正常MERCHANT及ACTIVE OWNER可处理已接旧单，暂停/停业/下架不阻止履约；不重新报价，不要求当前APPROVED。账号/成员停用仍禁止所有操作及重放。无新资金，模拟开关关闭不影响合法旧单履约。

首次开始须ACCEPTED/PAID/ACTIVE、合法支付且未退款，锁后startAt<=now<endAt。等于开始允许，等于结束拒绝；不提前或补开始。写IN_SERVICE、固定startedAt、版本+1和一条START事件，保持ACTIVE。未到店或已过结束不自动退款/完成，管理员异常后续实现。

首次完成须IN_SERVICE/PAID/ACTIVE及合法startedAt，不可跳过开始；now>=startedAt，等于允许。不设最短时长，可提前或晚于预约结束完成。写COMPLETED、completedAt、版本+1、COMPLETE事件，ACTIVE转CONSUMED；保留原预约区间，不能缩短或释放。提前完成不把剩余已售时间再次开放，晚完成不自动延长原区间。

原支付/金额不变，refund=null、reviewed=false。开始/完成合法重复返回原时间事实与当前详情，不覆盖版本/事件；完成后重复开始仅重放，不恢复服务中。CLOSED始终拒绝，不恢复履约。

## 事务与占用保护

RC写，复用账号→会话→店铺S→OWNER→日期保护行→订单/预约当前读→状态/占用/事件，提交前复查会话；任一步失败回滚。时间判定在相关业务锁后，首次开始时刻固定，重放不重新判断首次窗口。数据库条件更新校验来源状态及服务器版本，不引入客户端幂等键或版本。

公开候选及创建一直排除ACTIVE/CONSUMED；完成提交前后都占用，不出现可重复售卖空档。未结束CONSUMED继续受排班/营业时间保护；人员停用/解绑沿用ADR-0022允许完成后调整的规则，不静默扩大保护。

复用原Controller/Service、状态/时间字段和占用枚举，无新Java文件、迁移、XML、依赖或基础设施。仍V1～V10共19张业务表；运行43个操作、完整62个、19个待开发。评价、列表/事件、管理员异常和打印仍分别推进。实际检查范围见履约指南。
