# ADR-0014：每周营业时间

- 日期：2026-10-19（Asia/Shanghai）。
- 状态：用户回复“采用并实现”，确认 [营业时间提案](../merchant-business-hours-design.md)。
- 范围：整周配置 PUT 与现有店铺响应中的真实时段，不包含排班、订单或节假日。

以 Asia/Shanghai 的每周重复计划保存，星期为严格整数 1～7，时间严格 HH:mm、分钟精度，开始早于结束，不跨午夜，不接受 24:00。原始请求每天最多 4 段、整周最多 28 段；重叠和重复拒绝，相邻合并后按星期/开始排序。没有配置的星期休息，空数组清空整周。完整替换不修改手动营业开关，开关与时段仍不能替代后续服务/预约资格检查。

沿用 ACTIVE / MERCHANT + APPROVED + ACTIVE OWNER 权限及同一个 shop.version。排序合并后没有实际变化不写 SQL，但仍检查版本和权限；实际变化才整体替换时段并递增一次版本。BIGINT 上限允许无变化，不允许更新。账号、归属、分类、审核信息与历史不变。

V4 建立 shop_business_hour，以外键、唯一索引和 CHECK 约束基本合法性；重叠及请求数量由事务内的规范化逻辑保证。账号 → 会话 → 店铺 → 本人 OWNER → 时段为写入锁顺序，时段使用锁后当前读比较。删除、全部插入、版本递增同事务，异常整体回滚；写入前与最终版本更新前复查会话有效期。没有改写 V1/V2/V3，没有新增依赖。

本人店铺与管理员详情/分页采用 REPEATABLE READ 只读事务，在同一快照内组合店铺版本和时段。已有经营 PATCH 与审核写事务使用时段当前读，避免把等待前的旧快照组合进新版本。管理员分页用一条参数绑定的批量 SQL 读取本页时段，避免逐店查询；动态 SQL 只生成参数位置，不拼接 ID 值。所有 MerchantShopView 返回真实 businessHours，未配置返回 []。

PUT 仍位于“06 商家经营配置”，总规划不扩容；同步接口注解、运行快照、规划和 [点击验收](../merchant-business-hours.md)。当前只验证配置本身；排班、预约、订单接入前必须另行落实存量预约保护，不能声称本任务已经支持带存量订单的时间修改。

2026-10-21 后续交付：按 [ADR-0018](0018-merchant-schedule.md) 增加今天及之后的已有排班覆盖保护，包括停用人员；实际营业时间变更不覆盖则 409 SCHEDULE_CONFLICT，历史日期不限制修改。排班/营业时间写使用 RC 和统一店铺入口；预约存量保护仍待实现。
