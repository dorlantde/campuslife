# ADR-0023：预约模拟支付与待接单全额退款

- 日期：2026-10-22。
- 状态：用户已明确“采用并实现”。详细规则见[已确认方案](../booking-payment-design.md)，人工验收见[支付指南](../booking-payments.md)。

## 决定与理由

在 order 模块新增一个本人模拟支付接口，同时扩展待接单取消、接单超时和创建锁内清理。支付成功后必须有真实持久化的支付事实和 ACTIVE 占用；退款必须与关闭和释放原子提交。只实现同步模拟资金，不引入第三方支付、余额、部分退款、REFUNDING 或消息基础设施。

V10 建立 payment_record 和 refund_record。各订单最多一笔成功支付、一笔全额退款；支付事实不因退款而改写。数据库以唯一键、外键及正金额检查兜底，金额和跨表状态一致性由事务校验。

首次付款使用冻结 payableAmount，锁后 now < paymentDeadline；paidAt 固定为锁内判定时刻，acceptanceDeadline=paidAt+30分钟。店铺经营资格失效阻止首次付款，手动停业/下架/改价不影响旧单。合法重复付款返回原事实，不改时间/版本。已退款或未付取消后不允许重新付款。

待接单本人取消全额退款；now >= acceptanceDeadline 则按 ACCEPTANCE_TIMEOUT 退款关闭，提交后才返回409。一次关闭仅递增一次版本并写一条事件。已接单及后续取消留给商家履约任务。

## 事务与开关

写事务 RC：本人账号 → 会话 → 店铺 S → 日期保护行 → 订单/占用 → 流水/事件；SYSTEM 不锁登录身份。定位读取不作为锁后状态判断，订单和预约用独立锁查询重新读取。退款与支付失败全部回滚；提交前复查会话。保持配置店铺 X 在日期行之前，禁止反向锁经营账号。

`campuslife.mock-payment.enabled=${MOCK_PAYMENT_ENABLED:false}` 默认关闭，本机 VS Code 开发项显式开启。所有新增支付/退款均受开关保护；已有成功事实可读取及幂等重放。关闭期间已付到期单保留占用并记录订单提示，恢复后按原截止时间补处理；未付款释放继续执行。

扫描每30秒、启动首扫，两组分别最多100条，每单独立事务。创建时只清理重叠到期单，退款关闭与新建同事务；开关关闭则保留 ACTIVE 并返回 BOOKING_CONFLICT。候选查询保持只读 RR，不提前释放未提交退款的时段。

## 后果与边界

当前运行37个操作，完整规划62个，25个待开发；V1～V10 共19张业务表。商家接单/拒单、开始/完成、管理员异常和打印支付仍未开放。精确边界、真实 MySQL 并发与回滚验证记录见支付指南，不把 schema 校验当作业务测试。
