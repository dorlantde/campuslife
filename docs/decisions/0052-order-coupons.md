# ADR-0052 两类订单用券

日期：2026-10-30。业务依据：用户已采用ADR-0050第2～6节及M08.2执行顺序。本项将既有决定落实至订单，不引入Lua/MQ或改变前端范围。验证证据见[专项报告](../reports/order-coupons-2026-10-30.md)。

## 选择与原因

增加学生POST /booking-quotes；扩展打印报价、两类创建的可选userCouponId。省略/null不使用优惠，显式非法/不可用券报错，不能静默按原价下单。报价短只读RR，无预留、锁价或续期；匿名候选保持原价，不带个人券。下单重新核对服务/价目版本、同店归属、有效窗口、门槛及期望实付。

V19给user_coupon增加AVAILABLE/LOCKED/USED/EXPIRED、当前订单指针及版本，新建order_coupon保留券规则与LOCKED/USED/RELEASED处理事实。一单一快照；历史券ID不唯一，才能在未付款释放后再次用于新订单。当前订单指针唯一、FK、状态/金额/时间CHECK和事务内校验共同保护。新增一表，原订单的三个金额字段直接承接优惠，无券订单不补虚假记录。

原价达门槛才减固定整数分，减额小于门槛，实付至少1分。下单占用；支付在原15分钟期限内核销，不重新判断券到期或活动停止。未支付取消/超时按释放时刻返回AVAILABLE或EXPIRED。支付后任何已有合法退款仅退冻结实付、券保持USED。发行数量不回补。

## 事务与锁

沿既有RC账号→会话→店铺S→日期/文件→订单/扩展资源，再取持有券X锁；锁后选取毫秒时刻，订单金额、资源/文件保护、用券事实、资金及原事件同事务。券版本MAX拒绝写入409。没有新增独立提交点、事务内磁盘IO或外部组件。

预约创建会关闭相交的过期旧单。先按订单ID取得这些已有订单锁，再把旧单关联券和新单选中券去重按ID升序全部锁定；随后判时、清理旧单及占用新券。禁止循环中取得券后再寻找其他旧订单。这样避免不同日期请求交错取得多张券。支付、学生取消和扫描在原资源锁后取得关联券，判时不使用等待前的时刻。退款不释放USED。

创建时先插入事务内待支付订单以获得FK目标，再写券快照和最终金额/创建时刻/支付期限；任何失败整体回滚，允许自增ID空洞。新增SQL写入有成本，本项不声称吞吐提升。

## 兼容与展示

不选券时沿用原规范化摘要字节；选券用独立BOOKING_COUPON_V1/PRINT_COUPON_V1前缀及券ID纳入摘要。已有键先查原订单，不因当前券不可用、店铺停止或文件清理而重建；内容变化仍409。两条创建路径仍按原操作隔离。

本人/商家/管理员详情加入nullable coupon快照，旧无券订单为null。原列表已包含originalAmount/discountAmount/payableAmount，不逐单查询券。本人券列表与领取结果读取真实状态，空闲过期派生但GET不写；原领取库存/唯一键规则不变。券不授予文件下载权限。

## 边界

单实例私有文件存储、模拟资金默认关闭、原授权与配置规则保持。新增券字段不是Redis一致性协议；Lua、RabbitMQ、失败补偿与消息受理仍须后续定稿和真实组件联测。本项自动测试与人工点击验收分开记录，不把生成指南视为已人工验收。
