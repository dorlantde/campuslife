# ADR-0027：管理员核实预约异常并全额模拟退款关闭

- 日期：2026-10-22。
- 状态：用户已明确“采用并实现”。细则见[确认方案](../admin-booking-exception-design.md)，操作与实际验证见[验收指南](../admin-booking-exception.md)。

## 决定与理由

在order模块新增管理员预约详情、核实退款关闭两个接口。仅正常ADMIN与有效会话，无店铺归属限制；目标学生/商家账号或OWNER停用、店铺暂停/停业不阻止处理旧单。管理员自身停用仍禁止所有操作及重放。详情只读RR，不执行超时退款。

关闭须提交核实原因和读取时expectedVersion，防止核实期间订单已经开始/完成。原因去首尾空白1～300个Unicode码点，版本为规范非负BIGINT字符串。首次仅BOOKING、PAID、ACTIVE占用，状态PENDING_ACCEPTANCE/ACCEPTED/IN_SERVICE；合法原成功支付、未退款。不限制普通取消时间窗口，不要求先等到预约结束。COMPLETED不能退款，未付款不能走该入口。

新增全额成功模拟退款必须开启默认关闭的模拟资金开关；金额固定为冻结应付金额并核对原支付，不允许客户端传金额、状态或管理员ID。保留原支付及已发生的履约时间，以ADMIN_EXCEPTION关闭，保存实际ADMIN账号及核实原因；主单、退款、占用、事件一次原子提交，version+1。

未开始ACTIVE→RELEASED；IN_SERVICE关闭ACTIVE→CONSUMED，保留整个原预约区间，不截短、不延长。沿用ADR-0022/0026的公开候选/创建排除及配置保护，避免服务开始后退款再次售卖原时段。

## 版本、重试与竞争

对已CLOSED，仅最后ADMIN_EXCEPTION事件与当前版本对应、同一管理员、同一归一化原因、expectedVersion=当前version−1且原退款/占用事实一致时重放200，不覆盖时间、版本或原因；其他关闭请求409 ORDER_STATE_CONFLICT。成功重放无需开启资金开关，仍验证当前管理员权限。

非CLOSED先核对版本，过期409 CONFIG_VERSION_CONFLICT；版本匹配但状态不合法409 ORDER_STATE_CONFLICT。实际递增已达版本上限同样拒绝。管理员读取后商家发生开始/完成，须重新读取与核实，不能自动沿旧请求退款。

PENDING_ACCEPTANCE仍按原期限扫描。管理员与扫描先提交者决定ADMIN_EXCEPTION或ACCEPTANCE_TIMEOUT，另一方不能改写或重复退款；管理员接口不代跑超时事务。普通支付、接单和扫描的既有期限规则不变。

## 事务和范围取舍

RC写：当前管理员账号→会话→店铺S→日期保护行→订单/预约当前读→资金及事件，提交前复查会话。不锁目标学生/经营账号，不要求OWNER资格，避免反向锁并保留停用后的处理出口。退款、关闭、占用、事件或会话失效任一步故障全部回滚；数据库竞争503可重试。

复用现有订单事件记录核实操作人及原因，不新增争议/工单表或多级审批。新增2个生产Java文件，当前150个；运行45个操作、完整62个（45已实现、17待开发），V1～V10仍19张业务表，无新迁移、依赖或XML。投诉、证据上传、部分退款、已完成售后、打印及订单列表/事件查询留待后续任务。
