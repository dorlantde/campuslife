# ADR-0029：商家本店订单分页列表

- 日期：2026-10-23。
- 状态：用户已明确“采用并实现”。细则见[确认方案](../merchant-order-list-design.md)，交付与实际验证见[验收指南](../merchant-order-list.md)。

## 决定与理由

新增GET /api/v1/merchant/orders，让商家在本店列表中找到预约再使用已有详情和履约接口。正常MERCHANT及ACTIVE OWNER才可用；无OWNER所属店铺404，成员PENDING / DISABLED为403，空页或PRINT不能绕过。服务端确定shopId，查询始终限定本店BOOKING，不接受客户端改变归属；可查看本店所有学生的六种状态订单。

沿用本店订单详情的历史读取资格：不要求当前APPROVED，暂停/停业/下架仍可查旧单，学生停用也不隐藏。此决定不放宽接单的经营资格要求。复用OrderPage / OrderSummary，冻结名称、应付金额、预约起止；退款不将原金额改为0。不额外返回学生个人信息、备注、事件、版本或资金对象。

类型/状态及分页沿用ADR-0028：省略/BOOKING查预约，PRINT暂空页但完整校验权限和参数；主状态精确大写六选一，默认page=1/size=20，size1～100、page最大INT，正十进制数字允许前导零，其余非法400。createdAt DESC、id DESC，long偏移，越末页200空items保留实际总数；无匹配totalPages=0。

## 一致性与取舍

RR只读事务从本人店铺读取开始固定快照，OWNER资格与count/page均用普通一致性读、相同本店/BOOKING/可选状态条件；联表一次返回页内快照，不逐单查详情/资金。快照建立后成员被停用，当前请求可能完成，下一请求拒绝；不为列表新增业务写锁。身份认证仍沿用已有账号/会话校验。

GET不触发关闭、释放、退款、版本/事件变化或到期状态推断，模拟资金开关关闭不影响查询。与已有写锁协议保持兼容，不反向锁学生账号；跨请求页码可能随新增或状态变化移动，不提供固定分页快照。

沿用order模块、现有Mapper/VO和V1～V10十九张业务表，无新迁移、插件、XML或缓存。复用ix_order_shop_status；未带状态筛选可能另行排序，不预先增加索引或承诺性能收益。运行操作47个、完整62/47/15；事件查询及打印业务仍待后续任务。实际执行范围见验收指南。
