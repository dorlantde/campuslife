# ADR-0051：MySQL同步领券与本人读取

2026-10-30，依据用户已确认的[ADR-0050](0050-coupon-business.md)及“进入下一项”授权实施M08.2-B。业务规则不再重复确认；前端暂停，订单用券、Lua和MQ仍未实施。

新增4操作：匿名GET shops/{shopId}/coupon-campaigns、正常学生POST coupon-claims、GET coupon-claims/{claimId}、GET me/coupons。V18增加user_coupon、coupon_claim_request两表，共27表、72操作。

领取RC锁序：学生账号X→本人会话X→店铺S→活动X→新持有券/成功请求。只读定位活动不授权，锁后按当前活动和公开店铺资格判断；不反向锁经营账号。库存条件更新、冻结持有券、成功请求同一事务；末尾会话到期全回滚。每活动每学生唯一约束＋账号/活动锁防重领与超发。issuedCount累计增加、不推进活动配置版本或updatedAt，故店主原发布/停止版本仍可用。

Idempotency-Key独立于订单创建键，1～64位字母数字下划线/短横线，按学生＋键精确区分大小写。本请求只有规范正十进制campaignId一个业务字段，因此持久存完整归一化ID进行精确等价比较，无需有损摘要；以后增加字段时必须扩展完整比较或版本化摘要。同键换活动409；同键同活动先返回原成功事实，不重判活动/店铺资格或窗口，但仍校验学生当前权限/会话。换键重复活动409。首成功201、重放200，均SUCCEEDED；失败事务不保留成功请求，不臆造异步PENDING/FAILED。锁竞争回滚503保留原键重试。

本人券冻结活动名称、门槛/减额、店铺、使用窗口和来源配置版本。B阶段是不可变的成功发行事实，AVAILABLE/EXPIRED由同一次读取时刻派生，不启动过期写任务、不扣回发行数量。当前无锁券/核销字段；C阶段再增加相应订单关联和状态迁移。LOCKED/USED筛选合法但当前空页，不能理解为已能核销。

读取短只读RR：私有入口复核学生/会话，身份、count/page、冻结规则同快照，返回前检查会话期限；历史不依赖店铺或经营者当前资格。分页默认1/20、最大100、long偏移，claimedAt/id倒序；shopId/state可选。匿名目录沿原公开资格，仅PUBLISHED及claimStart≤now<claimEnd，停业可展示，售罄保留并显示0剩余；查询不预留，剩余不是必领承诺。错误token仍拒绝。

数据库约束覆盖学生/活动限领、学生/请求键唯一、成功请求与券一一对应、外键、金额和使用期限；跨记录归属由同一写事务及读取一致性校验保证。本阶段不增加order_coupon或消息表，模拟支付/退款、原订单和M02缓存核心保持。

验证及使用见[同步领券指南](../coupon-claims.md)、[报告](../reports/coupon-claims-2026-10-30.md)。并发验收用独立真实MySQL，不能只凭mock或HTTP201声称不超发。
