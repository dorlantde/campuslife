# ADR-0036：商家打印确认与本店查询

- 日期：2026-10-24。
- 状态：用户明确“采用并实现”；精确规则见[确认方案](../merchant-print-confirmation-design.md)，操作和实际验证见[验收指南](../merchant-print-confirmation.md)。

## 决定与理由

扩展既有商家列表、详情、事件、接单、拒单五个入口支持PRINT，保持原BOOKING规则。复用订单、打印明细、唯一资金事实及事件；不新增路径、表、迁移、依赖或基础设施。运行54个操作，完整规划62/54/8，V1～V12、21张业务表、184个生产Java文件保持。

正常MERCHANT及本店ACTIVE OWNER才可查询和处理；所属店铺由服务器固定。不存在/跨店404，本店成员失效403。读取各状态冻结历史，暂停、停业、服务下架、学生停用、文件删除不隐藏旧单。列表省略类型包含BOOKING/PRINT，指定类型分别筛选；RR内资格、count和page共用快照，沿用原分页和倒序，不逐单读详情或资金。PRINT预约时间null，进度为真实QUEUED/ABORTED。

详情和事件沿用既有字段，不增加学生账号资料或存储位置；事件保留原操作者ID及原因。GET不退款关单、不续期、不合成事件或推断超时状态。详情/事件的资格与事实来自同一RR快照，下一请求重新判断权限。

## 接单、拒单及重放

首次接单须当前APPROVED、PENDING_ACCEPTANCE/PAID/QUEUED，锁后now严格早于接单期限；PRINT没有预约开始限制。确认匹配的成功支付、无退款，文件属于订单学生且AVAILABLE/expiresAt=NULL，版本可递增。只写ACCEPTED、acceptedAt、版本+1和MERCHANT ACCEPT事件，资金及文件期限不变，资金开关关闭仍可执行。

停业、营业时间结束、改价或服务停用不妨碍合法旧单；文件只校验保护元数据，不等待实例互斥或读磁盘。这与付款采用相同取舍，磁盘问题由实际下载发现。重复合法接单仍须当前APPROVED/有效成员；不重判首次窗口或文件元数据，不重写时间、版本、事件；关闭订单不能恢复。

拒单reason严格字符串，strip后1～300 Unicode码点，拒绝未知字段。期限前待接单打印全额模拟退款，CLOSED/REFUNDED/ABORTED；MERCHANT_REJECT、closeNote、refund.reason_note和事件reason保存归一化原因，事件操作者明确MERCHANT。店铺暂停仍可拒单；同原因合法重放200且不重复写入，不同原因或其他状态409。

合法动作到达接单期限时，先按SYSTEM ACCEPTANCE_TIMEOUT全额退款关闭并提交，再在事务外返回409 ACCEPTANCE_DEADLINE_PASSED；已有超时关闭重试仍409。权限/店铺准入和输入失败不触发退款。所有新退款受原模拟开关保护，关闭时503并保持原事实；成功事实重放不依赖开关。

## 原子性与并发

商家写RC：商家账号X→会话X→本店店铺S→OWNER当前资格→文件X→主订单X→打印明细X→资金/事件，提交前复核会话。系统沿原店铺S→文件X→订单协议。不反向锁目标学生账号，不跨店锁其他引用订单。

与学生取消、扫描及同文件新建在文件行协调；先提交的合法状态决定后续结果，唯一约束兜底资金去重。退款、状态、进度、事件及全部引用期限同事务：仍有未终结引用则NULL，最后终结后最晚终结时间+7天。任一必要写入失败全部回滚。接单不更新文件版本，无期限变更不因文件版本上限失败。

商家动作返回使用锁后主订单/打印明细，避免MyBatis普通定位读缓存的旧状态。只读保持普通RR快照。共享商家路径按冻结类型分派，打印写事务放PrintOrderService/PrintOrderTransactions，列表复用OrderListMapper注解SQL，不引入XML。

## 阶段边界

商家PDF内容读取、接单后无法履约取消、打印中/待取件/取件及管理员PRINT异常未开放。原商家cancel/start/complete和管理员预约入口仍对PRINT返回404。PRINT接单后学生取消409，待接单扫描不再退款，文件持续保护；本阶段已接单测试单保持ACCEPTED，打印完整履约闭环待后续任务。
