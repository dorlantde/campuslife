# ADR-0049：最小前端与分批联调

日期：2026-10-29。状态：**用户明确“采用该方案”**，批准[M05.1具体方案](../minimal-frontend-design.md)。本记录确认选型与范围；实际交付按[路线图](../roadmap.md)的M05.2批次维护，不将批准视为全部页面实现。

## 问题与决定

V1已有62个真实接口，但Swagger操作不适合完整演示学生、商家与管理员协作。需要可日常联调的最小界面，同时保留Java后端实习项目的技术深化主线，控制UI投入。

采用独立`frontend/`：Vue 3、Vite、TypeScript、Vue Router手写路由及Element Plus；原生fetch统一请求，轻量响应式会话，暂不使用额外状态管理/请求框架。同一工程按服务端角色提供工作区，按13个页面模块映射61业务操作；健康检查不建管理页面。依次交付A工程/认证/浏览、B入驻/审核/经营配置、C打印整链、D预约/异常/其余管理。

本地使用项目自有Node/npm与锁文件；开发服务器仅监听127.0.0.1，通过同源`/api/v1`代理原后端。构建产物单独输出dist，普通Maven构建不自动包含前端，M06另行确定反向代理部署。不放开后端全局CORS，不修改原VS Code凭据。

会话使用标签页sessionStorage，刷新后GET /me复核；每标签一个账号。过期、撤销、账号停用清除会话，普通角色403保留；以会话代次拒绝旧响应写入新账号。存储可被同源脚本读取，不能据此声称防XSS；内容纯文本渲染，密码不持久化，token不进入URL/日志。

金额保持整数分，ID/版本保持字符串。时间按上海展示，预约UTC原值提交。创建请求沿用原幂等键/冻结正文；网络失败不等于服务端回滚，409也可能已提交期限关闭。客户端不自动换版本/金额重试业务写入，不自行推断关单或退款成功。文件下载必须携带Bearer并验证PDF响应。

## 边界与取舍

- 管理员没有全部订单/评价列表接口，相应页面按ID核实处理；不为凑后台补新接口。商家申请/经营资料以已有后端权限为准。
- 理发仍要求提前2小时，实际预约区间内开始；页面不放宽规则。人工末段尚未执行时须如实记录，隔离时钟测试不替代浏览器履约。
- 不显示未实现的领券、消息或排行入口；后续M05.3增量接入，不追加新业务。
- A批仅实现认证/资料与目录/详情/服务/评价浏览、角色导航壳。其余页面未实现时不显示可操作入口。
- 短期采用组件库既有控件与普通CSS。按需注册已使用组件、页面懒加载，不引入全量后台模板或视觉资源外链。

## 验证

各批记录类型检查、构建、关键客户端边界测试及真实浏览器结果。联调使用自有临时MySQL/文件根，测试账号与数据仅在隔离环境生成；不访问用户现有项目数据库，不创建公开管理员默认密码。生产ADMIN继续仅使用原本机初始化流程。测试夹具的虚构角色账号不是生产初始化方式。

真实数据库仍负责权限、版本、事务和幂等；UI路由与按钮只改善体验。批准本方案没有授权公网发布、用户数据迁移或删除。
