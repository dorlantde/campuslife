# ADR-0048：详情评分统计的MySQL版本门控缓存

- 日期：2026-10-28；状态：用户明确“采用并实现（推荐）”。[确认方案](../redis-rating-cache-design.md)、[运行与验收](../redis-rating-cache.md)。实际验证范围以[本轮报告](../reports/redis-rating-cache-2026-10-28.md)为准。

后续M02.3已完成[两轮量化故障与对照](../reports/redis-rating-cache-measurement-2026-10-28.md)：热门受益、普通/零评价中位更慢且版本维护有写成本，保留可关闭方案及原协议，不扩其它缓存。下文“后续另测”的安排指本决策批准时，最新测量证据以上述报告为准；不将短闭环结果视作线上容量或SLA。

## 问题与决定

C06实际发现热门店详情重复扫描VISIBLE评价求SUM/COUNT。保留V1同响应只读RR、公开资格及现场营业状态承诺，首轮只缓存详情评分统计；列表、公开评价正文与昵称、业务写操作及其它GET不使用此缓存。没有新增HTTP路径/响应字段，仍62操作。

新增V16 `shop_rating_revision(shop_id PK/FK, revision BIGINT>0)`，共24张应用表；无行虚拟版本0，首次实际评价变化upsert为1，之后单行原子递增。升级时为已有任意评价的店铺回填1，含全部HIDDEN；评价事实不变。FK在父店铺删除时级联清理技术元数据，既有业务外键不变，没有新增店铺删除入口。

首次成功提交VISIBLE、首次成功隐藏在原RC事务内最后推进版本；账号→会话→店铺S→订单/评价→统计版本，版本之后不再请求其它业务行锁。新增的同店版本行争用需纳入写成本验证，不将shop S升级X或改变商家配置版本。失败/到期全部回滚；重复评价拒绝、同管理员同原因隐藏重放不推进。缓存关闭或Redis离线仍推进；版本到上限拒绝变更，不回绕。没有新增MQ、outbox、订单事务或评价业务版本。

## 读与回填

详情外层NOT_SUPPORTED编排调用独立RR组件。开启时资格/资料/统计版本一个普通联表查询，营业时间普通读取；按namespace/shopId/revision读精确统计缓存。缺失或Redis异常时SUM/COUNT在同一个RR内执行，平均分沿原BigDecimal两位HALF_UP，零评价null/0。预计命中2条业务SQL、未命中3条；关闭缓存走原3条路径。认证过滤器工作另计。

原RR快照可以选旧版本键；更新后的新快照只能选新版本。评价事实与版本同事务提交即逻辑失效旧键；旧请求只能回填旧键，不需要依赖删除成功、延迟双删或异步删除重试保证正确性。Redis不参与MySQL事务；命中可复用的依据是相同版本统计集合不可变。手工SQL或未来新评价写入口必须维护该协议。

事务成功返回并释放连接后外层发布本次已提交读取结果及尝试Redis SET NX＋TTL；事务失败不发布/回填，Redis写失败不改变业务成功。最多256个实例内在途键，等待最多20 ms；相同版本可复用已提交结果，否则在自己RR回源。无后台加载线程池、分布式锁或多级本地持久缓存，不保证所有并发只有一次聚合。

## 客户端与故障

采用Boot4.1.1管理的Spring Data Redis4.1.1/Lettuce7.5.2.RELEASE；显式StringRedisTemplate及Jackson3字段编解码，限制载荷/版本/统计范围，不使用原生对象序列化、默认多态或Spring Cache注解隐藏事务顺序。Redis8.2.4官方镜像固定digest，GET及带TTL的SET NX无需Lua/Redisson。

缓存默认关闭，Redis自动配置由本模块条件化配置取代；关闭时没有Redis客户端连接工厂。开启但Redis离线仍可启动并从MySQL读。连接/命令超时200/50 ms，待处理队列256、断连拒绝新命令，异常后绕过5秒、单恢复探测；实际延迟另测。正统计TTL300～360秒、零统计30～45秒，合法空值可缓存；非法JSON/版本视为未命中并只清理精确坏键。保留内部命中、回源、错误及在途指标，不改变公开响应。

开发与测试使用不同命名空间/自有容器；回环端口首次选择后显式固定，避免Docker动态宿主端口在重启时变化。开发Start只写Git忽略的专用本机配置，不读改MySQL/JWT或VS Code凭据；部署缺少本机文件时默认关闭。缓存数据可丢弃，128MiB/allkeys-lru/无持久化不适用于未来优惠券受理事实；M08须另行隔离和定稿。数据库恢复/ID重用须更换命名空间。

升级须停止旧应用写入，禁止已启用版本协议的新旧写入口并行；代理本次只操作自有临时数据库，正式库由用户正常重启应用迁移。本轮核心读写/迁移/故障验证与M02.3系统化故障及同条件性能对照分开，不将技术接入或SQL条数下降当作已证实的性能收益。
