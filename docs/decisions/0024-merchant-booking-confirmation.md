# ADR-0024：商家预约确认与已接单学生取消

- 日期：2026-10-22。
- 状态：用户已明确“采用并实现”。详细规则见[确认方案](../merchant-booking-confirmation-design.md)，验收见[商家预约确认指南](../merchant-booking-confirmation.md)。

## 决定与理由

新增本店预约详情、接单、拒单三个操作，并落实基线中已接单理发距开始至少1小时可取消的学生权利。接单产生真实ACCEPTED状态，取消权随之接入，避免状态可达而基线能力缺失。复用order模块及V9/V10共19张业务表，无新迁移或依赖。

商家须正常MERCHANT且为本店ACTIVE OWNER；跨店、不存在、非BOOKING统一404。接单须APPROVED，暂停后不能新增履约承诺；详情与拒单允许正常账号/有效店主继续处理存量，避免暂停店铺无法退款。手动停业、下架、改价不影响原单快照。账号/成员停用仍禁止操作，待接单超时由系统处理。

接单仅已付款待确认、ACTIVE占用，锁后严格早于接单截止及预约开始。成功写acceptedAt、ACCEPT事件及版本+1，不修改资金或占用；重复返回原接单事实与当前详情。拒单必填去首尾空白后1～300码点原因，整笔全额退款并MERCHANT_REJECT关闭、释放；同原因重放不写入，异原因409不覆盖历史。原因保存到订单closeNote、退款reason_note及商家事件。

接单或拒单在锁内发现已到30分钟期限，先按ACCEPTANCE_TIMEOUT退款关闭，再由事务外返回409。已接单本人取消按锁后startAt-now>=1小时判断，等于允许；不足409 CANCEL_WINDOW_CLOSED，成功全额退款并USER_CANCEL关闭释放。已取消重放不重新判断窗口。

## 原子性与边界

沿用RC写、RR读：操作者账号→会话→店铺S→商家OWNER复核→日期保护行→主单/预约当前读→流水/事件。系统省略身份锁，不反向锁学生或经营账号；提交前复查当前会话。接单与超时、学生取消、拒单争用同一日期/订单锁，只有合法迁移提交；已退款不恢复接单，已接单不被待确认扫描退款。

接单不生成资金，因此合法接单无需开启模拟资金；任何新增退款（包括超时和已接单学生取消）均受默认关闭的模拟资金开关保护，失败503且原子回滚。已存在的同原因拒单或USER_CANCEL事实可重放。操作不引入额外幂等键或客户端expectedVersion，服务器状态及版本条件更新与唯一流水约束协同保护。

本轮运行40个操作，完整62个、22个待开发。商家列表/事件查询、商家已接单后无法履约取消、开始/完成、管理员异常和打印订单仍待后续推进。已接单且无法直接取消的测试单会保持ACCEPTED，不能据此假称完整履约闭环已完成。验证范围及实际结果见验收指南。
