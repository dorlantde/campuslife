# 本人PDF受控下载：已确认方案

- 日期：2026-10-23（Asia/Shanghai）。
- 状态：用户明确“采用并实现”；决策见[ADR-0032](decisions/0032-file-download.md)，实际交付与验证见[下载验收](file-download.md)。
- 依据：[ADR-0031](decisions/0031-print-file-upload.md)、[上传验收](print-file-upload.md)、[接口契约](v1-api-contract.md)。

## 1. 推荐任务与边界

新增一个GET `/api/v1/files/{fileId}/content`，让正常学生通过带登录凭证的请求下载本人有效PDF原文件。上传和元数据已有真实文件ID、页数及生命周期，本轮补齐内容读取，随后可继续打印报价。

推荐只开放STUDENT本人。接口契约中的商家凭本店ACCEPTED / IN_SERVICE打印订单访问仍是后续目标，目前没有打印订单，不能用商家身份直接取得文件权限；ADMIN也没有默认内容读取权限。本轮不新增商家下载入口、公开链接、URL登录凭证、预览页面或打印订单。

预计运行操作51→52，完整规划仍62，已实现51→52、待开发11→10。沿用file模块、本地私有存储与20 MiB上传限制，无新表、迁移、依赖或存储服务；实现后再以实际OpenAPI检查更新交付状态。

## 2. 权限、有效期与错误

fileId沿用规范正BIGINT字符串，不允许前导零；非法格式400 VALIDATION_FAILED。无登录或失效会话401，账号停用403，正常商家/ADMIN角色403。有效学生请求先判归属，再判文件生命周期：

| 文件情况 | 结果 |
|---|---|
| 不存在、他人文件、内部UPLOADING | 404 RESOURCE_NOT_FOUND，不读取文件内容 |
| 本人AVAILABLE，expiresAt为空或当前时间早于截止 | 可继续核对本地对象并下载 |
| 本人达到截止（等于即过期）、DELETING或DELETED | 410 FILE_EXPIRED，即使磁盘仍有对象 |
| 本人有效记录，但存储根不匹配、对象丢失、长度不符、不可读或路径安全检查失败 | 503 FILE_STORAGE_UNAVAILABLE，不伪装为已过期，不自动修改元数据 |

当前上传均有24小时期限；允许读取AVAILABLE且expiresAt为空是对未来订单保护字段的兼容，不表示本轮已实现订单引用或续期。

**新增建议：以获得文件互斥后、输出响应前的身份与有效期复核作为本次下载授权边界。** 等待期间退出、停用或到期的请求不能凭旧认证结果继续；复核通过后发生到期、退出或停用，本次已获准传输允许完成，后续请求重新校验并拒绝失效身份/文件。校验使用新只读快照，校验快照建立后才提交的账号/会话变化属于后续变化，不声称能收回已经发送的内容。

下载不续期，不改文件状态、版本或删除时间，不触发同步清理、重新解析PDF、订单事件或资金操作。对象内容按上传后的私有文件读取，下载时核对普通文件及实际长度，不每次重新解析或完整预计算SHA-256；本轮不提供磁盘内容被外部程序篡改后的自动修复或完整性审计。

## 3. 返回与调试方式

成功200为原PDF字节，不包装ApiResponse；声明`Content-Type: application/pdf`、准确`Content-Length`、`Content-Disposition: attachment`。附件名使用安全ASCII回退名及编码后的UTF-8原名，支持中文，不能直接拼接未经编码的文件名到响应头。

响应使用`Cache-Control: no-store`与`X-Content-Type-Options: nosniff`；不生成存储路径、key或长期直链，不输出文件正文或登录凭证到日志。浏览器另存为的本地副本不受服务端到期清理控制。

V1使用完整文件下载，不实现分段、断点续传、条件缓存或服务端预览。Range及条件请求头不触发206或304，合法下载仍返回完整200，也不声明支持Accept-Ranges；避免引入另一套部分内容权限和清理边界。

写入响应前失败沿用统一JSON错误。传输开始后若客户端断开或磁盘读取失败，关闭流、释放互斥并记录必要的请求追踪及文件ID，不在PDF后追加JSON；此时不能保证将已提交的200改为JSON错误。若还未提交响应，可以清除尚未提交的PDF响应头/缓冲并返回统一错误。

人工验收使用Swagger先登录、Authorize，再上传并复制fileId，执行下载，保存响应文件；Apifox使用Bearer授权并保存二进制响应。地址栏直接打开路径不自动携带Bearer凭证，不能据此认定接口故障。具体点击指南及实际页面表现随实现验证后交付。

## 4. 下载与清理并发

沿用现有单实例、按存储key映射的有界互斥，避免下载中途被本应用清理删除：

1. 先按已认证学生及归属查询文件记录，取得内部定位信息；无权请求不打开磁盘文件。定位信息不返回客户端。
2. 在数据库事务外取得该文件的实例互斥；等待时不持有数据库事务或行锁。
3. 获得互斥后开启新的短只读RR事务，重新读取当前账号、会话和文件，使用同一快照及一次Clock判定身份、归属、状态和期限，不依赖等待前的结果。使用普通一致性读，不为GET取得账号/会话/文件业务写锁。
4. 事务结束后核对当前存储根标识、受限随机key路径、非链接普通文件及长度，打开文件并流式传输；文件IO和客户端等待均在数据库事务外。使用有界缓冲，不把整个20 MiB文件加载为响应字节数组。
5. 传输结束、异常或断开均关闭文件句柄并在finally释放互斥。获取、传输、释放保持在同一处理线程，避免跨线程释放现有线程归属锁。

清理继续使用tryLock，遇到正在传输的文件跳过，后续扫描重试；不等待慢客户端下载，也不先将它标记为DELETING。即使物理删除延迟，新的请求达到逻辑期限仍返回410。若清理先获得互斥并提交DELETING，下载随后复核会拒绝，不能恢复状态。

这是单实例下避免“校验有效后、传输前被删除”的简单方案。慢传输会推迟该文件的物理清理；相同互斥桶内的下载可能串行，当前不承诺并发吞吐或即时删除。暂不引入读租约、分布式锁或文件副本；未来打印订单接入仍须按ADR-0031补齐引用保护和清理协调，不能以本轮下载替代订单授权。

## 5. 完成标准与验证计划

实施同步补充ADR、接口注解、二进制成功及JSON错误的OpenAPI定义、两份导入文件和点击验收指南。以下为计划，尚未执行或声称通过：

1. 实际HTTP下载与上传原字节一致，中文/特殊字符附件名、PDF类型、长度、禁止缓存和无路径泄漏正确；Range及条件头仍完整200，错误响应保持JSON。
2. 使用独立真实MySQL验证本人/他人、商家/管理员、未登录、退出/到期/停用、规范ID和UPLOADING隔离；验证失效文件包括等于截止时刻，归属优先，不因下载改状态/版本/期限。
3. 验证缺失/长度不符/错误存储根/链接或重解析点对象返回503且不改变元数据，不泄露磁盘路径。覆盖传输前故障及响应已提交后的读取失败/断开，确保不追加JSON并回收资源。
4. 使用受控并发时序及真实MySQL，验证下载等待期间的退出、停用、期限变化会被新快照复核；复核后变化按已批准的授权边界处理，不把mock身份变化当作数据库验证。
5. 在传输阻塞时推进到期扫描，确认不进入DELETING或删除对象；结束/异常释放后扫描可完成回收。反向验证清理先提交时下载拒绝，并检查数据库事务不覆盖传输等待。
6. 回归上传、本人元数据、清理恢复、相关身份及OpenAPI；不访问用户现有数据库或真实上传目录，不因文档提案运行构建或宣称实现。

本次已确认：学生本人下载的阶段范围、授权复核后的传输可完成、流式下载与清理互斥，以及完整文件下载边界。原有上传大小/页数、24小时到期、归属优先和商家必须依赖打印订单的原则继续沿用。
