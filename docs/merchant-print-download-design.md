# 商家打印PDF受控下载：已确认方案

- 日期：2026-10-25；校园业务时区Asia/Shanghai，接口时间UTC。
- 状态：用户明确“采用并实现”；已按[ADR-0038](decisions/0038-merchant-print-download.md)落实，操作与实际验证见[指南](merchant-print-download.md)。
- 依据：[本人下载ADR-0032](decisions/0032-file-download.md)、[文件引用ADR-0034](decisions/0034-print-orders.md)、[商家打印确认ADR-0036](decisions/0036-merchant-print-confirmation.md)、[接单后取消ADR-0037](decisions/0037-merchant-print-cancellation.md)。

## 1. 推荐范围与理由

扩展现有GET `/api/v1/files/{fileId}/content`支持正常商家按本店有效打印订单下载。学生本人下载规则保持；无新增路径、orderId查询参数、表、迁移、依赖或基础设施。运行仍54个操作，完整62/54/8，V1～V12、21张业务表。

商家从本店已接单PRINT详情取得printing.fileId，用商家Bearer调用该下载入口。服务器按fileId和本店订单关系决定权限，不接受客户端shopId/studentId改变归属，不提供磁盘位置、公共链接或永久下载URL。

复用文件ID入口与既有流传输/互斥，比增加另一套商家下载路径更直接；同一文件可能关联多笔订单，授权使用“本店是否仍有至少一笔符合条件的订单”，不依赖客户端指定哪一单，也不额外维护授权副本。

本轮不实现开始打印、待取件/取件、管理员内容访问或打印异常退款。商家上传和学生本人元数据入口仍保持原STUDENT限制；扩展下载不等于扩展这些入口。

## 2. 商家授权条件与状态边界

正常MERCHANT、有效会话和本店ACTIVE OWNER才可获得内容授权；无所属店铺404，所属成员失效403。校验当前账号/会话/角色，不仅信任请求最初携带的角色。

本轮推荐只对当前已经开放的已接单未开始组合授权，须存在至少一笔：

- 归属服务器确定的本店，类型PRINT，print_detail.file_id为目标文件。
- 主状态ACCEPTED、付款状态PAID、打印进度QUEUED，acceptedAt非空。
- startedAt、readyAt、pickedUpAt为空，文件与订单学生归属一致。

打印中、待取件等IN_SERVICE内容授权留到对应履约任务确认和实现，不提前凭枚举开放。本轮正常路径是先接单再下载；下载后发现无法履约，可使用已实现的商家cancel入口承担全额退款责任。

| 情况 | 推荐行为 |
|---|---|
| 本店至少一笔符合条件的已接单PRINT关联此文件 | 可按受控下载规则读取PDF |
| 仅未付或已付待接单订单关联 | 404，不在接单前开放学生内容 |
| 本店关联单全部关闭/完成，文件仍在7天保留期 | 404；文件保留不等于商家仍有内容权限 |
| 本店一单取消，但另一笔本店合格关联仍存在 | 仍可下载；授权来自另一笔有效任务 |
| 仅其他店有合格关联，或只有本店不合格关联 | 404，不因同文件跨店引用获得权限 |
| 停业/休息/店铺暂停，或服务/价目停用、改价 | 有效商家/OWNER仍可处理已接任务；不要求当前APPROVED或营业 |
| 目标学生停用 | 不撤销正常商家已接任务授权；不锁目标学生账号 |
| 原30分钟接单期限已过，订单仍合法ACCEPTED | 可下载；原期限不继续限制已接任务 |
| ADMIN、其他不支持角色 | 403，管理员没有默认PDF权限 |

不因文件属于当前商家账号、曾有历史订单或知道fileId而绕过上述订单关系。本店其他订单或跨店订单的资金和内容不附加到响应中。

## 3. 文件、响应与错误

先校验身份、商家归属/成员及有效任务授权，无授权的文件统一404，不能通过生命周期或磁盘异常探测他人文件。已授权未终结引用应保持文件AVAILABLE且expiresAt=NULL；保护元数据异常503 FILE_STORAGE_UNAVAILABLE，不把异常保护状态当成商家继续读取的许可。文件归属不匹配不授予内容权限。

实际对象仍由既有安全读取检查存储根标识、随机key、非链接普通文件和长度；不存在/不可读/长度或根异常503，不擅改文件状态、订单状态或资金。超过上传原24小时但受有效订单保护的文件不据原上传时间判过期。学生本人原404/410及到期规则保持ADR-0032，不被商家分支替代。

成功200原PDF二进制附件：application/pdf、实际长度、安全ASCII回退及UTF-8附件名、Cache-Control: no-store、nosniff，不包装JSON。V1沿用完整200，Range/条件头不启用206/304、断点续传或浏览器缓存。

无下载次数上限或新增限流设施；使用原有界文件互斥及缓冲流，不整文件加载、不重复PDF解析/哈希。下载不修改订单/文件版本、期限、打印进度、事件或资金，也不受模拟资金开关限制。

规范fileId非法400；会话无效401，账号/角色/OWNER不符403；无店/无授权/目标不可见404；已授权文件保护/存储异常503。数据库暂时竞争按项目既有可重试错误处理，不能把权限失败误报为磁盘故障。

## 4. 授权时点、取消与清理

沿本人下载的两次短只读RR：第一次检查当前身份/商家资格/有效关联及文件，定位内部对象key；事务结束后等待原文件互斥；取得互斥后建立新的短RR快照，完整复核当前账号、会话、OWNER、本店任务关系及文件。两次查询的key/存储根不一致拒绝503，拒绝复用等待前的许可或MyBatis旧事务缓存。

复核使用普通一致性读，不取账号/店铺/文件/订单业务行锁，不在数据库事务中等待磁盘或客户端。现有file模块已经通过引用Mapper读取打印关联，本轮在这一既有边界内补只读商家授权，不让FileTransactions调用打印写事务或生成资金。

授权边界是取得互斥后新RR快照：等待期间已提交的退出/账号或OWNER停用、角色改变、本店最后有效任务取消等，必须拒绝本次请求；快照建立后提交的取消/停用则不主动中断已经获准的传输。下一请求重新检查；已经保存到客户端的副本无法收回。

商家取消仍沿ADR-0037执行元数据事务，不等待传输互斥。取消可以在下载期间提交退款/关闭和7天期限；下载所持互斥使清理tryLock跳过该文件，获准传输可完成，句柄关闭且互斥释放后清理再重试。无业务数据库锁覆盖传输，也不增加读租约或分布式锁。若仍有本店另一笔有效关联，下次下载可依该关联授权；只有其他店的关联则不能续用本店已取消的授权。

写流前失败保持统一JSON；已提交PDF传输发生IO异常沿ADR-0032终止连接，不追加JSON。所有完成/失败路径关闭输入句柄并释放互斥，不记录正文、Bearer或磁盘位置。

## 5. 验收范围（实际执行记录见指南）

1. Swagger/Apifox：学生上传/创建/付款→商家接单→从本店详情取fileId→商家Bearer下载并核对原PDF；商家取消最后有效关联后，同入口404，学生仍按本人规则在保留期内下载。
2. 真实MySQL/HTTP验证未付/待接单/合格已接单/关闭/完成及合成未来进度组合、同文件本店多单和跨店引用、文件学生归属一致性。合成状态只验拒绝，不代表打印履约已开放。
3. 身份/会话/角色/OWNER/无店/跨店/ADMIN、暂停/停业/下架、学生停用、原期限经过、资金关闭；学生本人原授权与生命周期回归。
4. 用门闩控制文件互斥等待，等待期间提交退出、成员停用或最后有效单取消，验证取得互斥后新RR拒绝；不得只用mock授权声称真实MySQL快照正确。
5. 受控传输期间商家取消可以提交，当前获准传输完成，下次请求无授权404；文件清理跳过活动传输，释放后按真实期限恢复。验证不持有业务行锁/事务跨IO，不反向锁学生账号。
6. 实际字节、附件头/no-store、完整200、对象缺失/长度/根异常、首读失败及提交后中断；异常后句柄和互斥释放，不能PDF尾接JSON。
7. 所有下载前后订单、资金、事件、文件期限/版本不因下载变化；原打印接拒单/取消、学生下载和文件清理相关回归。同步注解、两份OpenAPI、ADR和点击指南，使用独立临时MySQL与测试文件根。

本次已确认商家内容可见状态、按本店任一有效关联授权、暂停店铺处理旧任务，以及取消/停用与已获准传输的并发边界。授权范围已落实，实际执行结果及验证范围以指南记录为准。
