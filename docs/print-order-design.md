# 打印待支付订单与文件引用保护：已确认方案

- 日期：2026-10-24（America/New_York）；校园业务时区继续为Asia/Shanghai，接口时间继续UTC。
- 状态：用户明确“采用并实现”；决策见[ADR-0034](decisions/0034-print-orders.md)，交付及验收见[打印订单指南](print-orders.md)。
- 依据：[业务基线](decisions/0001-v1-baseline.md)、[预约订单ADR-0022](decisions/0022-booking-orders.md)、[文件ADR-0031](decisions/0031-print-file-upload.md)、[下载ADR-0032](decisions/0032-file-download.md)、[报价ADR-0033](decisions/0033-print-quotes.md)、[接口契约](v1-api-contract.md)。

## 1. 推荐范围与完成目标

形成“报价→创建打印待支付订单→本人查询→取消或15分钟超时关闭”的小闭环，同时保证关联文件不会被误删。同一文件可以被本人多笔订单引用，不能在第一笔取消时就开始删除。

| 接口或任务 | 本轮确认范围 |
|---|---|
| POST /api/v1/orders/prints | 新增创建；Idempotency-Key必填，首次201、相同请求重放200 |
| GET /api/v1/orders/{orderId} | 扩展本人详情支持PRINT，返回冻结打印快照 |
| POST /api/v1/orders/{orderId}/cancel | 扩展未支付PRINT取消，关闭与文件保留期同事务 |
| GET /api/v1/orders | PRINT不再为空页；省略orderType查询本人两类订单，保持分页/排序规则 |
| GET /api/v1/orders/{orderId}/events | 扩展本人PRINT事件，沿用已有展示规则 |
| 打印未支付扫描及文件清理 | 新增打印超时关闭；接入全部引用保护及终结后7天保留 |

本轮只产生PENDING_PAYMENT / NOT_PAID / QUEUED，以及CLOSED / NOT_PAID / ABORTED，不生成支付或退款流水，不受模拟资金开关限制。打印支付、商家接单/履约/内容读取、管理员打印异常、取件与评价继续后续开发。现有支付、商家和管理员预约入口仍只处理BOOKING，遇PRINT不得误入预约事务；商家列表的PRINT阶段空页本轮保持。

预计只新增一个运行操作，53→54；完整规划仍62，54已实现/8待开发。其余是既有学生接口扩展，不虚增接口数量。

## 2. 创建请求、资格与价格

沿用报价的serviceId、fileId、paperSize、colorMode、sideMode、copies，增加必填expectedPriceVersion、expectedPayableAmount，以及可选note：

- ID为规范正BIGINT字符串；A4、BW/COLOR、SINGLE/DOUBLE精确枚举；copies为严格JSON整数1～100。
- expectedPriceVersion为该规格价目的0～Long.MAX_VALUE规范十进制字符串，不是店铺/服务版本。
- expectedPayableAmount为严格JSON整数1～5000000000分；不接受字符串、小数或指数形式，不修改预约自身的金额上限。
- note省略、null或去首尾空白后为空，统一为null；非空最多300个Unicode码点，沿用预约备注习惯。未知字段拒绝，不收studentId、shopId、pageCount、单价、priceRuleId或取件时间。
- Idempotency-Key沿用1～64位ASCII字母/数字/下划线/短横线，区分大小写。缺少/非法键400 IDEMPOTENCY_KEY_REQUIRED，其他格式错误400 VALIDATION_FAILED。

仅正常STUDENT及有效会话，文件须本人AVAILABLE、未到expiresAt，等于截止即失效。新订单还须当前存储根中的真实对象可打开、为安全普通文件且实际长度匹配；复用已有存储安全检查，不重新解析整份PDF或做完整哈希审计。不存在/他人/UPLOADING为404，本人到期/DELETING/DELETED为410；有效记录的磁盘/存储根异常503 FILE_STORAGE_UNAVAILABLE。

店铺须满足已批准的公开资格，分类PRINT；服务是本店上架PRINT，目标价目启用。店铺/服务不存在、非PRINT或公开资格无效404；服务下架409 SERVICE_UNAVAILABLE，缺少/停用规格409 PRINT_SPEC_UNAVAILABLE。不以参考起价兜底。锁内按实际页数和当前价目重算，价格版本或预期金额不一致409 QUOTE_CHANGED，无订单或文件期限变更。

**已确认：创建必须当前营业。** businessEnabled=true，且锁后判定时刻位于上海当天营业区间[start,end)；手动停业、休息或未配营业时间均409 SHOP_UNAVAILABLE。这与ADR-0033允许停业估价并不冲突：学生可以提前看价，进入交易时再校验能否接单。打印不引入预约的提前2小时或15分钟起点网格，也不承诺预计完成/取件时间、打印容量或设备已连接。

## 3. 冻结、详情及历史查询

创建主订单、打印扩展、CREATE事件、完成幂等记录和文件保护必须同事务提交，任一失败全部回滚。创建时刻使用全部必要锁就绪后的服务端时刻，数据库时间按毫秒保存，paymentDeadline=createdAt+15分钟；提交前再次检查会话期限。

冻结店铺名、服务名、文件展示名、服务/文件ID、实际页数、份数、规格、纸张数、命中价目ID/版本、每面单价和原价/应付金额，优惠0/CNY。双面仍按每份分别取整算纸张，不把印刷面数或金额减半。名称、参考起价、规格停用及后续改价不改写已创建订单；后续支付只能针对冻结金额，支付本轮暂不开放。

OrderDetail保持原公共字段：PRINT时booking=null，printing为明确的打印对象，含fileId、fileName、pageCount、copies、paperSize、colorMode、sideMode、sheetCount、unitPriceAmount、progress、readyAt、pickedUpAt；本轮后两者null。payment/refund及尚未发生的履约时间null，reviewed=false。不返回存储key、路径、哈希或下载直链。BOOKING原响应值保持既有语义。

学生列表默认包含本人两类订单，指定BOOKING/PRINT分别筛选，仍按createdAt/id倒序、默认页1/大小20、最大100，total与items来自同一只读RR快照。打印摘要的预约时间为null、printingProgress为QUEUED或ABORTED。只读详情/列表/事件均不自动关单或续期；即使当前店铺停用、服务下架或PDF已物理删除，仍能读取本人冻结历史。

本人打印事件仍按eventSeq升序，CREATE序号0，正常取消由STUDENT、超时由SYSTEM记录；不为文件保留期变化合成订单事件，不增加REFUND事件或资金。

## 4. 幂等与重试

复用现有(account_id, operation, request_key)唯一键，打印使用CREATE_PRINT，预约继续CREATE_BOOKING。同一个字符串键可以分别用于两种创建操作；不改旧预约摘要、记录或命名空间。

打印摘要固定包含类型、全部规格/ID、份数、预期价目版本、预期金额及归一化备注，使用无歧义编码。同一学生/CREATE_PRINT/键、同摘要返回原订单当前详情，状态200并带Idempotency-Replayed: true，关闭后也不重新创建；异摘要409 IDEMPOTENCY_KEY_CONFLICT，不自动换键下单。不同学生的键互不冲突。

重放仍须验证当前身份及原订单归属，但不要求旧店铺仍营业、旧规格仍可用或原PDF仍在磁盘；不能因为文件到期而重新创建或延长文件保留期。返回原事实不触发超时关闭，过期仍待扫的订单也如实返回当前数据库状态。

唯一键竞争导致整笔回滚后，在新事务重新读取原结果；死锁/锁超时整笔回滚503 SERVICE_TEMPORARILY_UNAVAILABLE，保留原键重试，不从失败SQL中间继续。响应丢失不等于创建失败，同键重试不能产生第二张订单。

## 5. 文件生命周期：以全部关联订单为准

新增print_detail中的file_id就是引用事实，不另建一张可重复失真的引用计数表。文件元数据即使DELETED仍保留，因此历史订单外键不妨碍删除磁盘内容。

1. 首笔创建成功后，至少有一笔未终结PRINT引用，expiresAt=NULL；创建失败不得改变原上传有效期。
2. 同一有效文件可创建本人多笔订单，包含不同店铺。取消/超时关闭其中一笔，只要还有其他未终结引用，expiresAt仍为NULL。
3. 全部引用终结后，expiresAt=所有引用中最晚终结时刻+7天；本轮终结时刻是实际closedAt。**未支付取消/超时也采用7天保留，不恢复成上传时的24小时期限。** 后续完成路径接入时纳入completedAt。
4. 保留期内仍为AVAILABLE的文件可用新键再次创建，重新转为NULL保护；过期、DELETING或DELETED不能通过新订单复活。
5. 重复取消、重复扫描或创建重放不重写closedAt、不额外延长7天、不增加事件；仅期限实际变化时更新文件版本，已经为NULL且仍有未终结引用时不做无意义递增。

文件行是引用串行入口。创建、关闭及未来所有打印终态写入都先锁同一file_asset行，再处理订单/引用与保留期。文件清理标记DELETING前在该文件行锁内复核期限，并额外确认没有未终结PRINT引用；发现矛盾只跳过并记录必要标识，不删除文件或自动复活状态。清理不反向锁账号、店铺或订单。

最后一笔关闭的主订单/进度/事件/保留期必须同事务；重算只读其他关联订单，不同时锁其他店铺。这样两个店铺的订单同时关闭也不会各自误判“最后一笔”，或相互反向拿店铺锁。

## 6. 事务、磁盘与锁顺序

写事务沿用READ COMMITTED。打印写锁顺序：当前学生账号→会话→本单店铺S→文件行X→目标打印订单/扩展→事件/幂等记录。系统超时无学生账号锁，沿店铺S→文件行X→订单顺序，停用学生或暂停店铺不能阻止未支付旧单关闭。配置仍按原店铺X入口，不反向锁目标学生账号。

**创建还需要协调现有单实例文件互斥，不能在持有数据库行锁后等待它。** 建议流程：

1. 先做格式/身份及已存在创建键检查，合法重放可直接返回历史结果。
2. 新请求读取本人文件定位信息，在数据库事务外等待该文件现有互斥；等待时不持有账号/会话/文件行锁。
3. 持有互斥时在事务外打开对象、核对当前存储根及长度并关闭句柄；磁盘失败不创建订单。
4. 再进入短RC事务，重新验证身份、创建键、归属/文件定位、状态、有效期、营业资格、服务/价目及金额。全部锁就绪后取判定时刻；此前有效、等待后已过期/停业/退出的请求必须拒绝。
5. 原子写入订单与引用保护，结束事务后finally释放实例互斥。若文件在有效判定后于事务内自然跨过原24小时期限，创建与NULL保护一同提交；清理不能在锁内穿插删除。

清理和下载继续使用同一实例互斥；新创建若遇长下载会等待，期间不占用数据库行锁。取消/超时仅更改元数据，不取得实例互斥、不做磁盘IO，避免出现“数据库文件行→实例互斥”的反向路径。文件IO、PDF解析和客户端传输都不放入MySQL事务。仍沿用本地存储单实例限制，不新增分布式锁或对象存储服务。

## 7. 取消、超时与恢复

普通学生可取消本人PENDING_PAYMENT / NOT_PAID打印单，无须店铺当前营业或仍具接新单资格。严格早于paymentDeadline时关闭为USER_CANCEL；达到期限（等于也到期）则先提交PAYMENT_TIMEOUT、ABORTED及引用重算，外层再返回409 PAYMENT_DEADLINE_PASSED，不能因抛异常把关闭回滚。

同一USER_CANCEL重复请求返回原详情；已PAYMENT_TIMEOUT的重复取消返回同样期限错误，不再写入。其他状态409 ORDER_STATE_CONFLICT，本轮不走任何退款路径。

打印未支付扫描沿用每30秒、启动首扫、每批最多100条、每单独立事务、失败后重试的模式，独立于预约已有待支付/待接单扫描配额。只处理PRINT，锁后复核状态和期限；重复或并发扫描只有第一次写事件。测试显式关闭自动触发、直接调用同一方法，正常运行默认开启。

保护中的文件即使原24小时已过，未提交关闭的到期订单仍算未终结引用，继续保守保留；扫描恢复后按实际关闭时刻确定7天。文件清理仍按原60秒/100条扫描，只有保留期结束且无未终结引用才允许DELETING→物理删除→DELETED。

## 8. 数据与模块边界

新增V12及print_detail，20→21张业务表；不改旧迁移。扩展以order_id为PK/FK，含服务、文件、价目FK及冻结规格/名称/页数/份数/单价/版本/纸张数、进度和阶段时间，file_id建引用查询索引。数据库CHECK保护枚举、1～500页、1～100份、1～100000分/面、纸张公式及非负版本；本轮只写QUEUED/ABORTED，未来履约值存在不等于操作已开放。

在order模块增加独立PrintOrderService/Transactions及必要DTO/VO/Entity/Mapper，不把打印流程塞进BookingOrderTransactions。既有学生入口按冻结orderType分派，列表按类型合并历史；文件模块统一执行引用检查/保留期动作，打印模块决定订单动作，避免两套TTL算法。沿用注解SQL与MyBatis-Plus，不写XML，不引入Redis/MQ或新的应用模块。

## 9. 验收计划

以下为批准的验收范围；已执行项目和实际结果见[验收记录](print-orders.md#自动验证记录)，不能据此把未执行项声称为通过：

1. Swagger/Apifox从已启用规格报价复制版本和金额创建，核对201、PRINT快照、15分钟截止、本人列表/详情/CREATE事件；同键200且无额外订单。人工指南说明必须开启营业开关并配置当前上海时段，与“可在停业时报价”区分。
2. 实际MySQL/HTTP验证身份/归属/资源/规格/价格版本、严格金额及50亿分；开闭区间精确边界、休息/无营业时间、长锁等待后的身份/期限复核。旧预约限制不得被打印金额范围或类型分派放宽。
3. 真实并发验证相同键/异内容/不同键、文件将过期时创建对清理、下载对创建，以及商家改价/停业对创建；证明配置、引用和订单原子性，SQL异常或响应丢失不会产生半引用。
4. 验证一份文件两笔或跨店多笔，逐笔取消/超时、最后终结+7天、重放不续期、保留期内重新引用；同时关闭最后两笔、关闭与新创建竞争，必须按文件行串行得到正确保留期。
5. 验证清理先提交则创建拒绝，创建先提交则扫描不删除；注入订单/扩展/事件/幂等/期限更新失败，所有DB修改回滚。磁盘异常在事务外失败；输入/输出无路径泄漏，下载原行为及7天后410/物理回收正确。
6. 验证超时关闭先提交后409、重复扫描/重复取消、启动恢复、停用学生/暂停商家的旧单关闭。支付/商家/管理员预约接口不能误改PRINT，不生成资金；学生历史在文件删除后仍可读。
7. 按影响执行预约创建/支付/取消、列表/事件、报价/配置、文件上传/下载/清理及OpenAPI回归，使用独立临时MySQL和存储根。同步ADR、真实接口注解、两份导入文件和点击指南，不把纯mock结果当作锁正确性。

本次已确认：当前营业才能下单、待支付打印闭环及学生历史接入范围、创建操作幂等命名空间、全部引用终结后7天（含未支付关闭），以及文件与订单统一锁协议。支付及商家打印细则本轮不扩展。
