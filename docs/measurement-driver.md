# M06.2-B.2-B 请求、轮询与统计工具

C.1[资源登记/清理](measurement-resources.md)随后已独立验证；C.2组件指标/真实事实、C.3登录/健康与总入口仍待实现，不能把独立模块通过当作组合运行通过。

本模块消费[B.2-A夹具](measurement-fixture.md)的预期数据，负责一个测量段中的请求和HTTP观察；不启动应用或组件，不执行SQL，不自动进入下一段。源码位于独立的 `src/measurement/java/campuslife/measurement`，不加入生产JAR。B.2-C仍需接入真实登录、指标、健康停止信号、SQL/Redis事实核对及七服务生命周期；Pilot尚未执行。

## 固定请求与响应校验

`MeasurementScenario`读取真实导出的expected，核对FORMAL/PILOT来源、1000店/600公开的完整集合、180名学生及历史订单、500份评价统计和活动信息。分类ID由调用方从本轮字典核对后提供；受控检查使用原始字典1/2，不能据此跳过后续环境核对。

FORMAL每段固定600请求：热点详情180、普通五店详情180、分类首页60、关键词“稀有”30、无分类第20页30、本人历史订单60、60个不同学生的首次领取60。每段对应一个活动与一组学生；使用显式随机种子交错，幂等键由case/段/学生序号生成，不自动换键重试。PILOT为相同比例的60请求/6次首次领取。另提供6次详情首次访问与100次只读预热计划，不混入前台统计；阶段顺序由后续总适配器执行。

响应校验包括：公开店ID/名称/分类、评分和可见评价数、营业开关及上海时间边界、七天营业区间；列表总数/页数/完整顺序；本人订单的总数、顺序、ID、冻结名称/金额、状态和UTC时间。领取只接受正确的202/PENDING与相对Location、非重放头、活动/受理/期限元数据；201同步结果视为异常，不静默降级。409只将已知COUPON_SOLD_OUT单独归为预期售罄。

## 并发、截止与异步观察

`MeasurementDriver`使用私有固定前台线程，C只允许1/5/10，完整读取和校验一个响应后才取下一任务，最多600个有界任务。共用一个HTTP/1.1客户端，无自动HTTP重试、不跟随重定向；响应体最多256KiB。截止覆盖响应体读取，而不只等待响应头；超时取消对应异步HTTP任务。

真实策略为每请求3秒、前台90秒、前台结束后最多观察60秒；FIXED模式拒绝修改这些数值。尚未发送的任务保留UNSENT；截止附近的在途请求保留截断/UNKNOWN_POST。任何已发POST的未知结果都不能当作未入库或再发一个新请求。

单独一个轮询线程公平轮转，最多一个GET在途；每ID目标250ms、全局轮询启动间隔至少25ms（最多40次/秒）。按实际请求起点保存间隔，不承诺250ms的完成时间精度。HTTP/前台C不是全部线程或系统总并发；组件观测请求由B.2-C另外限制。

PENDING、SUCCEEDED、FAILED独立记录。校验结果归属、原受理/截止时间、成功券的冻结规则与时间、券ID唯一性；FAILED仅接受现有业务的四种安全失败码。观察截止仍未看到合法终态则保留删失项及观察等待下界，不能把它当作实际发行完成时间下界，也不能删掉后声称全体p95。截止以后到达的终态不计入本次已观察完成量。

重放必须同时满足：前台无未知POST、已受理请求全部观察到终态、没有停止信号，且调用方的 `verifiedDrain` 核对回调明确允许。最多6个原键，单列REPLAY，要求原请求ID、完整终态及券事实保持。**HTTP观察结束不等于SQL/Redis已核对排空**；B.2-C必须实现这个回调，不能用无条件true替代真实核对。受控检查中的true只表示临时响应端的模拟事实已知。

## 输出与统计

输出到新目录，已有目录拒绝覆盖：

| 文件 | 内容 |
|---|---|
| manifest.json | case/段/种子/并发、策略截止与轮询间隔、完整有序任务和幂等键 |
| requests.csv | 阶段、任务序号/类别/学生ID、相对起点/耗时、HTTP状态、结果类别和安全码；不含响应正文、Authorization或token |
| observations.json | 领取ID/学生、观察状态、已知失败码、删失原因、观察耗时或下界、轮询次数/最大起点间隔 |
| result.json | 完整记录、分组摘要、停止原因、线程收尾状态；最后原子发布，并返回四文件SHA256 |

使用nearest-rank计算p50/p95/max，空集合为null。阶段、请求类别和结果分别分组，成功与快速409不合并；UNSENT的零耗时不计分位数。前台吞吐只用实际客户端已结束尝试数和真实前台窗口，包含失败尝试时不能称为成功响应QPS；轮询、预热和重放不进入分母或前台600比例。

http202、通过验证的受理、观察成功/失败、删失、UNKNOWN_POST分别保存。成功观察耗时摘要明确为成功子集，不提供跨删失项的全体p95。工具不从HTTP结果推导实际新增券数或SQL吞吐，结果中保留 `sqlActualIssuanceNotMeasured=true`，由B.2-C独立核对。
