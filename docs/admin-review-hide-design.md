# 管理员隐藏评价：已确认方案

- 日期：2026-10-26；状态：用户明确“采用并实现”；落实见[ADR-0044](decisions/0044-admin-review-hide.md)，实际验证见[指南](admin-review-hide.md)。
- 依据：[学生评价 ADR-0042](decisions/0042-student-order-review.md)、[公开评价 ADR-0043](decisions/0043-public-shop-reviews.md)、[接口契约](v1-api-contract.md)、[数据库设计](v1-database-design.md)。旧草案已列隐藏入口，以下权限、重试及处理记录细则已由用户本次确认。

## 1. 范围与完成标准

新增已规划的 POST `/api/v1/admin/reviews/{reviewId}/hide`。正常 ADMIN 使用有效会话，填写原因后隐藏任意店铺的既有评价，保存首次处理记录；成功返回原有 OwnReviewView，visibility=HIDDEN。reviewId 可从既有本人评价或公开评价响应取得，本轮不增加管理员评价检索入口。

运行接口59→60，完整规划仍62，已实现60、待开发2（管理员账号列表和状态管理）。新增V14迁移，在既有order_review增加审核字段，业务表仍22张。沿order评价模块扩展写服务和Mapper，新增实际需要的管理员Controller/请求DTO；不增加基础设施。

完成标准：管理员能隐藏评价；后续公开评价分页、商家列表和详情评分不再计入该记录；本人仍可读，订单reviewed仍true，一单一次不变；权限、并发与回滚经真实MySQL验证；同步注解、两份OpenAPI及Swagger/Apifox点击指南。

本轮不做恢复公开、修改/删除评价、自动审核、商家回复、批量隐藏、管理员评价列表或账号管理。

## 2. 权限、请求与响应

只允许当前数据库身份为ACTIVE/ADMIN且会话有效的管理员。原作者、店铺、经营账号或OWNER停用/失效不阻止管理员处理历史评价；不要求店铺当前公开可见。学生及商家不能隐藏，ADMIN仍不因此获得PDF内容权限。

reviewId沿现有规范正BIGINT字符串校验，拒绝前导零、符号、空白和溢出；正文严格仅含reason字符串，使用strip去首尾空白，结果1～300个Unicode码点，保留内部换行。不接受null、空白、错误类型或额外字段。格式错误400 VALIDATION_FAILED；合法ID无记录404 RESOURCE_NOT_FOUND；认证和角色错误沿现有401/403。

首次仅VISIBLE→HIDDEN，返回200和原有六字段OwnReviewView（id、orderId、rating、content、visibility、createdAt），不返回作者账号详情。原评分、文字、创建时间、归属不变；审核原因不加入公开响应或本人评价响应。

## 3. 首次处理、重试与记录

推荐保存moderated_by（管理员账号FK）、moderation_reason（归一化后的原因）、moderated_at（锁后Clock时刻、UTC毫秒），与visibility在同一事务提交。管理员身份由服务端取得，不允许请求填写。

同一管理员、相同归一化原因，且原审核记录完整的HIDDEN重试200；保留首次处理人、原因、时间，不产生新事实。不同管理员或不同原因重试409 REVIEW_STATE_CONFLICT，不覆盖首次记录。两个管理员竞争时，先提交的处理记录保留；后一个依锁后状态判断重放或冲突。

不增加expectedVersion：评价内容及归属不可修改，此动作只有VISIBLE→HIDDEN一个方向，评价行互斥及首次记录足以解决竞争。取舍是本轮不能修改隐藏原因或恢复后再次隐藏；若以后增加这些操作，需要重新设计版本与多次审核历史。

首次锁后时间早于评价createdAt则409 REVIEW_TIME_INVALID，无写入；合法重试不重新判首次时间窗口。会话期限在写入后提交前再次校验，失效则整笔回滚。

V14增加三个可空字段，数据库约束审核字段要么全部为空，要么全部有值，且完整审核记录只允许HIDDEN、原因长度1～300、审核时间不早于createdAt；新增FK指向account。不伪造V13阶段已有HIDDEN记录的管理员或原因：允许这类历史记录保持三字段为空，隐藏请求遇到它返回409 REVIEW_STATE_CONFLICT，不能冒充本次成功重放。正常新提交评价仍为VISIBLE且三字段为空，本接口首次隐藏必须原子补齐全部字段。

## 4. 事务、锁与公开一致性

写事务沿项目RC。推荐锁序：当前管理员账号X→当前会话X→评价所属店铺S→评价X，锁后再次核对评价存在及所属店铺，然后判断状态和审核记录。首次定位只用于找到店铺，最终返回取锁后视图，避免MyBatis一级缓存返回旧visibility。事务失败时visibility和审核字段一起回滚。

不反向锁原学生或经营账号，不取订单、日期、文件锁或文件实例互斥，不访问磁盘。评价隐藏不修改订单/账号/店铺/文件版本、订单事件、资金、资源占用或文件期限；不受模拟资金开关影响。隐藏属于评价自身处理记录，不伪装成订单状态事件。

公开分页和统计继续使用已有VISIBLE过滤与各响应只读RR快照，无冗余评分需要更新。隐藏提交后新请求按新快照排除该记录并重算评分；已建立旧快照的请求可以完成，不承诺收回已经返回的内容。本人GET仍能读HIDDEN，reviewed=true，重复提交评价仍409；隐藏全部公开评价后公开评分null、数量0。

暂时数据库故障沿现有503 SERVICE_TEMPORARILY_UNAVAILABLE；不以成功响应掩盖回滚。无需缓存失效、消息或额外审核表，当前一次不可逆隐藏由评价行上的首次记录承载。

## 5. 验收安排

1. Swagger/Apifox以真实完成的预约和打印订单提交评价，取得reviewId；使用受控创建的管理员登录，填写原因隐藏，核对返回HIDDEN。查看公开评价、店铺列表/详情评分以及学生本人评价和订单reviewed。
2. 正常/停用/错误角色账号、撤销和过期会话；目标作者或经营方失效仍能处理；无效ID、未知评价、严格JSON、原因首尾空白/Unicode长度/超长/内部换行及时钟倒退。
3. 同人同原因重试保留首次时间；异人或异原因冲突；真实MySQL并发隐藏只有一次首次记录，等待锁后读取当前状态，失败或提交前会话失效全部回滚。
4. V13升级V14、字段分组/可见性/长度/时间约束和管理员FK；历史HIDDEN不伪造审核记录；正常VISIBLE新增与原一单唯一规则回归。
5. 隐藏与公开读取并发，旧RR响应内部一致、新请求排除，评分按剩余记录计算；本人仍可读且不能重发。证明订单版本/事件/流水/文件期限不变，无反向目标账号锁和磁盘IO。
6. 运行60、完整62/60/2、两份OpenAPI引用/模型/分组、迁移和可执行包启动检查。只用独立临时MySQL及测试自有文件根；实现后才记录实际执行命令、数量和结果，不把本方案当作测试通过记录。

本方案仅新增隐藏行为及首次审核记录。已按ADR-0044实现并同步当前进度；实际执行结果仅以验收指南为准。
