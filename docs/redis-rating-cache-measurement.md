# M02.3 缓存故障与性能对照方法

目标是评估[已实现的详情评分缓存](redis-rating-cache.md)的实际收益和维护代价。只测当前已确认的场景，不调整业务规则、缓存范围或默认事务承诺。[本轮报告](reports/redis-rating-cache-measurement-2026-10-28.md)单独记录真实结果和限制，不能以本方法文档存在代替验收。

## 同条件完整HTTP对照

显式运行的`RatingCacheAcceptance`不匹配默认Test/IT扫描，需要隔离脚本标记。复用已验证的PublicShopQueryFixture，写入前核对空库、campuslife_it、真实随机datadir和V16/24表；不访问用户正式库、上传目录或开发Redis。

每个独立MySQL/Redis实例运行1,000和10,000店两档（关联15,000/105,000条评价）。同一构建启动两个真正应用上下文和随机HTTP端口，缓存分别关闭/开启，使用相同临时数据库、固定测试Clock和每应用5连接的原Hikari配置。测试计数拦截器仅观察SQL，不替换读取实现；关闭/开启由真实配置决定，不通过mock返回缓存结果。

普通店20条评价、热门店5,020条评价、零评价店各自测试：

- 稳定读取：每请求从工作线程发起HTTP到读取完整响应并解析JSON计时；每场景预热，1/4/16工作线程，3轮，单线程每轮24次、多线程每轮48次。每轮交错随机化开关版本顺序，保存每个样本及分轮数据。
- 冷缓存：仅删除该自有命名空间的具体店铺/版本键，再分别发起4/16线程请求；记录实际回源、合并与等待超时，不预设所有并发只查一次。
- 批量到期：将三个自有键同时到期，再混合并发读，观察回源放大与有界在途登记。

逐响应核对完整data与对照，SQL捕获检查真实RR/readOnly；稳定关闭路径每请求3条业务SQL、一次聚合，开启路径总SQL=2×请求数＋实际聚合数。记录命中/未命中/绕过/异常、回源/合并、错误率、批次墙钟时间和每样本延迟。

这是固定工作线程的闭环实验，请求计时不包含进入工作线程之前的提交队列等待；批次完成速率包含该批次墙钟开销，不能当作开放负载的稳定容量或线上QPS。缓存开关仍需MySQL资格/版本/营业时间，不能声称完全不访问数据库。预热与冷缓存也不等于清空MySQL buffer pool或整机冷启动。

## 并发与真实故障

先核对Redis容器ID与本次随机所有权标签，再执行以下操作，只作用于自有测试容器：

| 场景 | 核对 |
|---|---|
| 六次真实隐藏与96次并发GET | 响应只属于按数据库原子提交推导的合法快照集合，最终请求见最后状态 |
| 暂停Redis容器 | 真实命令超时触发绕过，HTTP仍从MySQL读取；恢复必须观察到实际命中/回填，不能只凭键存在认定恢复 |
| Redis仅拒绝SET | 未命中回源后的真实SET失败不改变HTTP成功结果，恢复权限后可重建 |
| 停止Redis，期间提交隐藏，再启动 | 版本/隐藏仍同事务提交，离线读取正确，固定端点恢复后重建当前版本 |

已有M02.2的旧RR/晚回填、版本失败/溢出、离线新应用启动等核心证据仍有效；本任务不将已有验证重复计为新业务功能。暂停、ACL和进程启停都用finally恢复；脚本最终仅删除本次自有Redis并清理成功的临时MySQL。用户开发Redis保持运行。

## 新增版本维护的写成本

缓存关闭/开启两组都会维护统计版本，单靠它们不能测出相对V1的新增写成本。因此仅在测试Executor拦截器中构造“省略RatingRevisionMapper.advance”的对照，其余真实创建/隐藏事务相同；正式JAR中没有该拦截器或绕过配置。

写阶段在所有HTTP读阶段结束后运行，缓存关闭应用处理全部写入。测量前准备合法已完成订单、正常学生/管理员及真实会话；删除旧夹具评价、推进准备版本、创建会话均不计时。使用独立订单和多个管理员，避免仅一个管理员账号锁掩盖同店统计行争用。

1/8线程、3轮、每版本每轮32组，每组分别测真实创建及隐藏事务调用到提交返回的延迟；不把它称为完整HTTP写接口延迟。每批随机交错两个版本，保存原始事务样本、真实SQL量和实际版本语句耗时。批末额外推进一个技术版本，确保测试对照产生的集合不会被后续读取复用；这次不计入事务样本，SQL计数单独注明包含它。

另采集专用临时MySQL的Innodb_row_lock_time/Innodb_row_lock_waits差值。这是整个写批次的InnoDB行锁统计，可能同时包含账号、订单/评价和统计版本，不能全部归因于版本行；版本语句计时也包括JDBC/MyBatis和数据库执行，并非纯锁等待时间。

测试对照是“当前相同事务省略一条版本更新”，不是重新运行历史V1二进制，不提供生产可关闭版本维护的能力。真实HTTP读取和写成本阶段分开，不使用这条对照路径验证缓存正确性。

## 复现、归档与停止条件

在已有Java21/Maven/MySQL及Docker Linux引擎可用时，实际使用的入口为：

```powershell
.\scripts\benchmark-rating-cache.ps1 -Runs 2
```

每轮调用已有隔离脚本的Acceptance阶段，新建随机实例/命名空间、运行普通/Web及专项实验、mysql JAR检查后清理。每轮日志和`acceptance.json`存于`.cache/redis-it/<本次ID>/`；`progress.json`只是未完成检查点，不能当成功证据，只有专项所有断言通过才产生acceptance.json，completed.json还要求JAR检查和资源清理成功。
