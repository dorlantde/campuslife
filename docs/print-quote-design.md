# 学生打印报价：已确认方案

- 日期：2026-10-23（Asia/Shanghai）。
- 状态：用户明确“采用并实现”；决策见[ADR-0033](decisions/0033-print-quotes.md)，实际交付与验证见[报价验收](print-quotes.md)。
- 依据：[业务基线](decisions/0001-v1-baseline.md)、[打印价目ADR-0016](decisions/0016-merchant-print-prices.md)、[文件上传ADR-0031](decisions/0031-print-file-upload.md)、[文件下载ADR-0032](decisions/0032-file-download.md)、[接口契约](v1-api-contract.md)。

## 1. 推荐任务

新增一个POST `/api/v1/print-quotes`，让正常学生用本人已上传的有效PDF，选择已上架打印服务、规格和份数，取得服务端计算的金额及纸张数。成功200 ApiResponse<PrintQuote>，不创建订单、不占用或延长文件、不承诺价格保留。

这是从文件准备进入打印交易的下一步。先验收页数、印刷面与整数金额，再接打印下单，可避免把计价问题和订单/文件引用事务同时引入。本轮不开发打印订单、商家内容访问、支付、优惠券、装订或实际打印设备。

复用现有order模块，新增独立报价Controller、Service、DTO、VO和必要的注解Mapper/纯计算规则；商家模块继续维护配置，file模块继续负责文件生命周期，不将报价塞进上传服务。不引入新模块、表、迁移、依赖、缓存或分布式锁，沿用MyBatis-Plus及注解SQL，无XML。

预计运行操作52→53，完整规划仍62，已实现52→53、待开发10→9；实际数字以实现后的OpenAPI验证为准。

## 2. 请求与校验

JSON恰有以下六个必填、非null字段，拒绝未知字段：

| 字段 | 推荐规则 |
|---|---|
| serviceId | 规范正BIGINT字符串，禁止前导零、符号、空白或溢出 |
| fileId | 同上，由上传响应取得 |
| paperSize | 精确枚举A4 |
| colorMode | 精确枚举BW / COLOR |
| sideMode | 精确枚举SINGLE / DOUBLE |
| copies | 严格JSON整数1～100，等于边界允许；字符串、小数、指数形式不按整数自动转换 |

不接收客户端pageCount、sheetCount、单价、总价、ownerId、shopId或报价版本；它们由文件和当前服务/价目确定。枚举不自动去空白或转大小写。无须Idempotency-Key，因为接口没有业务写入；重复调用会按新的快照计算，不保证与上一次价格相同。

1～100份是此前草案中的建议，本次提议明确采用；沿用已批准的1～500页及每印刷面1～100000分，不另外限制总金额或把双面金额减半。

## 3. 资格、营业状态与错误

仅ACTIVE/STUDENT及有效会话，商家或ADMIN为403。业务校验顺序建议固定为：格式→当前学生身份/会话→文件归属及生命周期→店铺/服务资格→目标规格价目，避免因店铺或价格状态先暴露他人文件信息。

| 情况 | 推荐结果 |
|---|---|
| 字段缺失/null/未知、ID或枚举非法、份数不合规 | 400 VALIDATION_FAILED |
| 无登录、凭证无效、会话退出或到期 | 401，沿用认证错误码 |
| 账号停用，或身份不是STUDENT | 403 ACCOUNT_DISABLED / ROLE_FORBIDDEN |
| 文件不存在、他人文件、内部UPLOADING | 404 RESOURCE_NOT_FOUND |
| 本人文件达到expiresAt（等于即过期）、DELETING或DELETED | 410 FILE_EXPIRED |
| 服务不存在/下架/非PRINT，或店铺不存在/非PRINT/不符合公开可见资格 | 404 RESOURCE_NOT_FOUND，不返回部分报价 |
| 目标A4颜色/单双面价目不存在或停用 | 409 PRINT_SPEC_UNAVAILABLE，不用服务参考起价兜底 |

店铺可见性沿用ADR-0019：APPROVED + ACTIVE OWNER + 对应经营账号ACTIVE/MERCHANT。分类字典停用不隐藏已经获批店铺，不在报价时增加新限制。文件成功条件是本人AVAILABLE且未到期；expiresAt=null按有效处理，只为兼容未来订单保护，不宣称已接入引用。

**新增建议：停业、营业时间之外或未配置营业时间仍允许估价。** 本接口只计算价格，便于学生事先比较和准备，不表示店铺当前能接单，也不设置打印取件时间。未来创建打印订单必须重新判断经营资格及接单条件，具体营业时间与下单规则在下单任务中另行定稿；不因本次允许估价而批准休息时接单。

## 4. 计算与响应

实际PDF页数取file_asset.pdf_page_count，价格只取命中的启用print_price_rule.price_per_impression。服务的priceAmount是参考起价，不参与计算；单双面规格可以配置不同的每面单价。

- 印刷面数 = pageCount × copies。
- 单面纸张数 = pageCount × copies。
- 双面纸张数 = ((pageCount + 1) / 2，整数除法) × copies，即每份分别向上取整；不能合并多份后再取整。
- originalAmount = payableAmount = 印刷面数 × unitPriceAmount；discountAmount固定0，currency固定CNY。末页空白背面不收费，不另加纸张费。

| 场景 | 纸张数 | 金额 |
|---|---:|---:|
| 5页、2份、单面、每面20分 | 10 | 200分 |
| 5页、2份、双面、每面20分 | 6 | 200分 |
| 3页、2份、双面、每面20分 | 4 | 120分 |
| 1页、1份、双面、每面1分 | 1 | 1分 |
| 500页、100份、每面100000分 | 单面50000 / 双面25000 | 5000000000分 |

最大金额50亿分超过Java int上限；用long完成金额与中间乘法，使用精确整数运算及溢出检查，不用float/double、不截断为int。它仍在JavaScript安全整数范围内，响应金额保持JSON整数，ID与版本保持字符串。数据库异常数据不能悄悄给出错误金额或回退报价。

PrintQuote返回：serviceId、shopId、fileId、pageCount、copies、paperSize、colorMode、sideMode、sheetCount、priceRuleId、priceVersion、unitPriceAmount、originalAmount、discountAmount、payableAmount、currency。沿用接口草案字段，不加虚假的quoteId、锁价期限、优惠或公开文件链接。

priceVersion取该规格自己的版本，不能用服务版本或店铺版本代替。报价不保存；商家随后改价/停用、学生文件随后到期时，原响应只是历史计算结果。未来下单必须锁内重读文件、资格和价目，核对版本与预期金额再冻结快照，本轮不实现或宣称完成这套下单事务。

## 5. 事务与文件清理

采用一个短只读REPEATABLE_READ事务，普通一致性读取得当前学生账号/会话、文件及服务/店铺/价目；复用已有可见性条件。完成必要读取后用一次Clock统一判断会话期限与文件期限，满足时才返回完整报价。

整个响应来自同一快照，避免新单价配旧版本或服务和所属店铺不一致。商家改价、停用或清理在快照建立后提交，本次可以返回快照中的原结果，后续请求读取新状态；这不是锁价或文件保留承诺。等待过久导致判定时刻达到文件/会话期限仍应拒绝。

不持有账号、会话、店铺、服务、价目或文件业务行锁；不取得下载使用的实例文件互斥。不访问磁盘、重新解析PDF、清理文件或修改expiresAt/version/status，因此报价不会阻塞长下载或推迟物理删除。它验证数据库中的有效元数据，不作为磁盘对象健康检查；实际下载仍按ADR-0032核对对象。

## 6. 实施与验收标准

批准后同步补充ADR、Swagger注解、运行和完整规划两份OpenAPI、Swagger/Apifox点击指南。预计示例流程为：商家配置并启用打印服务/规格→学生上传PDF→复制serviceId/fileId→调用报价并核对金额；没有商家前置数据时指南须说明如何准备，不能只给不可复现的示例ID。

以下是验证计划，尚未执行或声称通过：

1. 纯计算覆盖BW/COLOR × SINGLE/DOUBLE四种规格、1/500页、1/100份、奇数页按份取整、单价边界和50亿分，确认整数与JSON类型不溢出、不按纸张误收费。
2. 真实MySQL/HTTP覆盖正常学生与他人隔离、角色/账号/会话、字段/ID/严格份数、过期精确边界及内部状态；目标资源无效不返回部分金额，验证文件错误优先于价目资格错误。
3. 真实配置验证可见店铺/PRINT上架服务/启用价目，缺少与停用规格均409；停业、休息、未配置营业时间可估价，分类停用不隐藏；参考起价与最终价目不一致时仍只用价目。
4. 控制真实并发事务，在读取快照后提交商家改价/停用或文件清理，核对一次报价中的版本和金额来自同一快照、下一请求看到变更；报价不等待业务行锁、不改文件或新增订单/资金/事件。
5. 执行报价、价目、相关文件/身份与OpenAPI回归，检查运行53、完整62/53/9及导入文件引用。MySQL与文件验收只用自有临时环境，不访问用户现有服务数据；不为这份文档提案运行构建。

本次已确认1～100份、停业仍可估价、规格不可用错误、金额上限推导及报价快照不保价的边界；已经批准的印刷面单价、PDF限制和学生文件隔离继续沿用。
