# M06.1-A0 MySQL 8.4 兼容验证复现

这是新部署的数据库兼容门槛，不升级本机MySQL、不连接项目开发库，也不是8.0→8.4存量升级工具。前端、Compose、TLS及Actuator仍属后续独立任务。采用范围见[ADR-0057](decisions/0057-single-instance-deployment.md)。

## 自动验证

前提：当前Windows开发机已安装项目Java21、Maven、Python、Docker Desktop Linux引擎；镜像允许从官方仓库拉取。项目自身的Java21目录仍由现有开发脚本约定提供。

在项目根目录执行已验证的入口：

```powershell
.\scripts\test-mysql84.ps1
```

仅复验迁移/元数据16项、卷重启及JAR启动时，可使用已验证的`.\scripts\test-mysql84.ps1 -Phase Startup`；它不能替代All的80项业务兼容检查。两次运行都使用各自新建的临时实例。

脚本使用官方`mysql:8.4.13`，固定镜像索引摘要`sha256:a81d043930e51745522bd5c430961cf8286f0a23f0a9a2a6e0108f7ea71b0902`。创建独立标签容器/卷/网络，仅向宿主回环随机端口发布3306；库名沿既有测试保护固定为`campuslife_it`，独立性由新容器/新卷/端口和随机凭据保证，不复用宿主3306。

随机root与项目账号凭据只落入该轮`.cache/mysql84-it/<随机身份>/secrets`；密码不放命令参数或报告。项目账号使用`caching_sha2_password`，仅授权测试项目库所需DDL/DML，保留启动Flyway的现有权限取舍。Windows挂载的客户端配置先复制到容器内并设0600；就绪探针只检查正式TCP服务，不使用初始化临时socket服务。

子进程显式屏蔽开发可选配置导入，使用自有文件根，关闭评分缓存、消息、券Redis、S3及自动扫描；测试中已有显式Clock/模拟资金规则仍由各用例控制。密码和JWT均重新随机生成，不要求用户输入或提供业务管理员账号。

验证分为：编译/打包→精选真实数据库用例→相同卷重启后的哨兵读写→重启后mysql模式JAR启动检查。既有`MysqlIntegrationIT`检查迁移、约束、中文/Emoji与UTC；新增`Mysql84CompatibilityIT`核对候选版本、原迁移/表数、严格模式、标准外键和账号权限。其余精选方法复用原预约、资金、优惠券、outbox及公开目录/评价测试，不重写并发方案。

本轮报告见[2026-11-02兼容记录](reports/mysql84-compatibility-2026-11-02.md)。只读查询依据同一确定性测试数据的结果、排序、筛选和RR快照断言判断语义；没有重新运行M01的千/万店性能对照，8.0测量值不能移用到8.4。

## 结果与清理

每次执行输出该轮`result.json`路径；保留构建/测试/启动/服务日志及脱敏用例摘要。`target`中的JUnit XML可能包含进程配置，只用于本机诊断，不复制进报告或对外分享；公开报告仅保存计数与必要非秘密事实。失败轮次保留，不按累计运行次数增加“不同检查”数量。

正常结束或验证失败都会按身份核对后清理本轮容器、卷、网络；清理成功再删除该轮生成的三个秘密文件。若进程被外力强杀，查看对应身份及资源标签，先核实归属再处理，禁止全局`prune`或清空其它卷。

停止自有测试不等于退出Docker Desktop/WSL；脚本不会关闭整个引擎。需要释放WSL内存时，由你结束其它相关工作后退出Docker Desktop，再自行执行`wsl --shutdown`。
