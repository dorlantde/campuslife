# M06.1-E 完整环境冷备恢复

按[ADR-0057](decisions/0057-single-instance-deployment.md)，使用自有showcase测试数据，验证五个持久卷及配置身份能恢复到全新项目/卷。本轮不操作阿里云，不读取开发库/用户上传根，不执行真实迁移或覆盖已有部署。

这与[普通Stop/Start](linux-deployment.md)不同：普通重启复用原卷；本项把停止后的数据归档，再写入全新空卷。当前工具强制限制为生成的`test`身份，不提供对真实部署的一键覆盖入口。

## 复现入口

保留当前已构建的应用镜像和固定组件镜像，在项目根目录执行：

```powershell
.\scripts\test-deploy-recovery.ps1
```

Python入口为`python scripts/test_deploy_recovery.py`；Linux可调用同一Python源文件，但本批真实宿主验收尚未执行。测试自行生成源/目标身份、虚构账号与文件，并显式启用模拟资金；不要求用户先手动部署。原Swagger业务路径、75操作/V24/32表保持。

## 备份窗口

1. 使用原业务完成异步领券、用券打印/付款、通知、取件与评价；原维护协议Pause，核对无PENDING领取和未发送outbox。
2. 写入独占冻结标记，停止Nginx和应用。受支持的Start及维护入口拒绝冻结实例；Status仍可读取。冻结不等于分布式锁，也不能阻止有宿主管理权限者绕过脚本操作Docker。
3. 用当前MySQL8.4容器中的mysqldump只计算数据库结构/数据的稳定摘要；不使用本机8.0客户端，不把SQL内容写入公开报告。
4. 停止所有持久组件，确认没有运行容器后，归档完整MySQL、RabbitMQ、券Redis AOF、SeaweedFS和LOCAL卷。评分Redis是可丢弃缓存，不备份。
5. 保存24份秘密材料、存储初始化回执、实例清单、部署配置和应用JAR；每文件/归档记录SHA256，最后才写完成回执。不完整备份不进入恢复。

数据库采用同版本、同架构MySQL完整datadir冷备，包含系统表、redo/undo等，不是在线复制若干表文件；恢复不顺带升级版本。本工具选择慢关闭并确认MySQL正常退出；MySQL官方将关机文件复制列为InnoDB冷备方式。[官方说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-backup.html)

RabbitMQ保存整个数据目录及cookie/配置，并保留原节点名；仅导出definitions不能保留消息。官方说明磁盘恢复要求原节点名，包含消息的备份应在节点停止后取得。[官方说明](https://www.rabbitmq.com/docs/backup)

本项在消费者停止后，额外把**已经消费成功的一条真实通知事件**按原ID和原payload重新放入持久队列；工具以HEX获取原字节并比对原摘要，JSON通过临时文件传递，避免客户端字符集或多重转义改变消息。这是受控重复投递夹具，不是新业务事实；它用于证明队列数据确实进入备份、恢复后消费幂等有效。其余待处理业务已排空，源环境不再接受新写。

## 恢复顺序与身份

恢复前核对完成回执、每个文件摘要、归档路径/类型、原配置和精确运行镜像。只使用新项目和新空卷，恢复专用nocopy覆盖避免镜像种子文件自动进入目标卷，仍拒绝覆盖已有卷；未完成的恢复禁止启动业务应用。

项目/容器/卷归属使用新的运行ID；另保留原持久数据身份`dataIdentity`，用于Rabbit节点/vhost、Redis前缀及S3桶/命名空间。普通实例默认数据身份等于自己的ID，旧清单兼容；不同数据身份仅允许显式隔离恢复，不能给普通部署静默换身份。

先启动MySQL、RabbitMQ、两个Redis和S3，在应用尚未启动时比较全部33张SQL表（含Flyway）的结构/数据摘要，确认原队列里的已知重复消息仍在。随后启动唯一业务应用，核对：

- 券Redis新runId由原协调器重建代次，ASYNC/PAUSED意图保留；人工Resume前不自动重开。
- 重复消息被确认消费，但通知/消费凭据/资金/优惠事实不重复。
- 原会话与授权下载有效，原S3和LOCAL内容可读，已过原期限的无引用测试文件由原清理器删除。
- 新上传成功且下载字节一致，原券库存约束下新异步领取最终成功，评分缓存可重建，管理readiness可读。

旧会话在独立备份复核中可通过原会话记录/备份密钥重建测试凭据，保持原到期时间，不修改旧会话；主流程保留原登录token。保留备份中的会话/活动以后会自然到期，不能靠延长期限重跑；到期后请使用单入口创建新测试数据。

依当前真实时间处理原期限，不修改系统时间或延长活动有效期。S3恢复后的新写单列验证；若首轮503，保留结果、进行至多3次有界探测，只有完整上传/回读/下载通过才认为具备放行条件，不放宽TLS、SDK超时或改成LOCAL回落。

恢复期间源环境保留且维持停止/冻结，不启动两份同一业务快照对外服务。失败保留源、备份与诊断证据；不得通过删原卷或重建空库掩盖恢复问题。

## 备份保管与限制

备份位于`.cache/deploy-recovery/<随机ID>/`，不提交Git、不放公开报告。Windows移除备份树继承授权，按目录/文件类型保留当前账户、所有者、SYSTEM及本机管理员访问，不授予普通Users/Everyone；POSIX使用0700私有目录。归档通过进程标准流读写，不把宿主备份目录挂入容器；读取/还原卷的短命辅助容器无网络，只挂载已核实的自有卷。

备份**未加密**，包含数据库账号材料、JWT和CA私钥；ACL与Git忽略不等于加密保管。需要离机备份/真实部署备份时，再单独确认加密、保留和传输策略。本批保留这些私有备份以支持复核，测试运行容器/卷及源目标实例秘密由脚本清理。

依赖固定镜像/运行环境仍需预先可用；本批不是整台主机或Docker镜像仓库的离线灾难恢复，也不证明跨版本、跨架构、在线无停机、异地恢复或HA。校验和用于检测损坏，不是第三方签名。

结果与失败轮次见[验收报告](reports/full-stack-recovery-2026-11-03.md)。M04-C曾出现的冷恢复新写超时原因仍需如实保留，不因本轮某次探测成功宣称已修复或承诺固定RTO/RPO。用户现已说明有阿里云Linux服务器；其系统/资源与部署尚未检查，本批不将本机容器结果当作阿里云验收。

## 独立复核入口

源实例已清理时，可对本机尚在原业务有效期内的自有完整备份独立复核。实际成功执行的输入为：

```powershell
python scripts/verify_deploy_recovery.py .cache/deploy-recovery/f0e290299f1b4b3d9452aca797511749
```

该工具恢复离线参考副本，重新冷备并在全新目标验证，结束清理两个实例运行资源，私有备份保留；只支持本工作区生成的test备份。原始登录token不会输出或保存到报告，重建的测试凭据只存在进程内存。固定镜像/JAR必须可用，原期限到达后此输入不能继续作为成功验收样本。
