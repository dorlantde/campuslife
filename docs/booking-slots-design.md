# 预约候选时段查询：已确认方案

- 日期：2026-10-21（Asia/Shanghai）。
- 状态：用户已确认“采用并实现”；实现决策见 [ADR-0021](decisions/0021-booking-slot-candidates.md)，使用与验证见[验收指南](booking-slots.md)。
- 已确认范围：实现已有规划 GET /api/v1/shops/{shopId}/booking-slots，先交付配置与排班计算的候选时段。不创建订单、不建立占用表、不模拟扣除占用。
- 依据：[业务基线](decisions/0001-v1-baseline.md)、[排班 ADR-0018](decisions/0018-merchant-schedule.md)、[公开目录 ADR-0019](decisions/0019-public-shop-catalog.md)、[公开人员 ADR-0020](decisions/0020-public-barbers.md)及[接口契约](v1-api-contract.md)。

## 1. 目标与阶段边界

商家已能维护营业时间、服务、人员绑定和排班，学生已能浏览服务及人员。本轮把这些配置连起来，回答“选择这项服务和这名人员，在指定日期有哪些候选开始时间”。

已确认的预约基线为未来 7 天、开始时间 15 分钟对齐、不跨午夜、至少提前 2 小时。排班已有今天至第 6 天的维护窗口，本次已确认查询日期边界、资格失败与空结果区别。

**当前只有 V1～V8 十三张表，没有订单或占用记录。** 原接口契约包含排除占用的完整目标，本次已批准并交付“候选时段计算”阶段，尚不宣称已经扣减真实订单占用或可以下单。沿用现有规划路径和响应字段，在 API 注解、接口摘要和验收指南说明这一阶段范围，不增加一套假的空占用实现或提前创建闲置表。

创建预约接口开放前，必须补齐真实占用查询、保护行锁内冲突复核，以及停用/解绑/排班/营业时间变更对有效预约的存量保护；占用状态和到期处理按订单任务另行定稿。不能因本次候选查询通过，就直接开放预约创建。

## 2. 查询资格与结果区别

| 项目 | 已确认规则 |
|---|---|
| 身份 | 允许匿名或任意有效登录角色；携带无效/过期/撤销 token 或停用账号，仍按已有规则失败 |
| 店铺 | 公开资格沿用 APPROVED + ACTIVE OWNER + ACTIVE/MERCHANT 账号，且必须为 HAIRCUT 分类；不存在、不可见或 PRINT 店统一 404 |
| 服务 | 必须为本店已上架 HAIRCUT 服务；不存在、跨店、下架或类型错误统一 404 |
| 人员 | 必须属于本店、已启用且实际绑定目标服务；不存在、跨店、停用或未绑定统一 404 |
| 资格与停业顺序 | 先核对店铺、服务、人员和绑定；资格无效不能因停业而被当作合法空结果 |
| 手动关闭营业开关 | 资格成立时返回 200，slots=[]，仍返回当前服务版本、价格和时长 |
| 当前不在营业时间 | 不直接据此清空；计算查询日期的营业时间，而非复用当前 openNow |
| 休息日/无排班/无营业时段 | 200，slots=[] |
| 服务时长放不进有效区间，或所有开始时间不足提前 2 小时 | 200，slots=[] |
| 分类字典停用 | 不隐藏已批准店铺，沿用 ADR-0015/0019；其他资格仍须成立 |

和公开人员目录不同，本接口必须选择一项服务与一名人员。人员目录“可以浏览”不保证该组合在指定日期产生候选时段。

## 3. 参数与时间边界

GET /api/v1/shops/{shopId}/booking-slots?serviceId=...&barberId=...&date=YYYY-MM-DD。

shopId、serviceId、barberId 均为必填的规范正十进制 BIGINT 字符串；格式错误、显式空值、0、负数、前导零或溢出为 400 VALIDATION_FAILED。资源不存在与不满足公开资格为 404 RESOURCE_NOT_FOUND，不区分可泄露跨店信息的具体原因。

date 必填，为 1000～9999 年的严格真实 YYYY-MM-DD 日期，不接受补零缺失、无效闰日或时区后缀。推荐预约查询窗口为 **Asia/Shanghai 今天至第 6 天，含首尾 7 个日期**；历史日期及第 7 天起返回 400，而非无限查询或静默返回空。

一次请求只从服务端注入 Clock 取一个判定时刻 now，用于校园今天和提前时间，客户端时间不参与。开始时刻须满足 **startAt >= now + 2 小时**，恰好提前 2 小时允许；按真实时刻比较，不先把当前分钟向下取整。只读查询以这一个时刻计算，执行中跨午夜不重复改变本次窗口；下一请求重新计算，结果不会预留资源。

例：校园当前 07:00:00，09:00 可作为候选；当前 07:00:00.001，09:00 已不足 2 小时，最早的 15 分钟网格为 09:15。查询明天时仍应用同一规则，不能仅凭日期不同就跳过提前校验。

## 4. 候选生成方式

1. 从服务配置取得真实 durationMinutes、priceAmount、version，不能由客户端传入时长或单价。理发时长仍为 15～240 分钟的 15 倍数。
2. 读取请求日期对应星期的营业区间和该人员当天的排班，按校园时区解释。数据库排班起止为 UTC，必须正确换算日期与时刻。
3. 取营业时间与排班的连续交集；每个候选的完整服务区间都必须位于同一段有效交集内，不能跨午休、排班断档或午夜。
4. 开始时间对齐校园时钟的 00/15/30/45 分，向上寻找满足条件的网格，不以区间起点任意平移步长。结束时间为开始加真实服务时长，允许恰好等于该段结束。
5. 保留满足提前 2 小时的候选，开始时间升序、去重。不同候选可以彼此重叠，因为它们是不同预约选择，不是已被同时占用的订单。

例：有效区间 09:00～10:00、服务 30 分钟，在提前条件满足时返回 09:00～09:30、09:15～09:45、09:30～10:00 三个候选。不能按服务时长每次跨 30 分钟而漏掉 09:15，也不能把三个选择当成同时可售的互不冲突预约。

营业时间仍保持分钟精度：若交集起点为 09:10，最早网格是 09:15；服务结束不能超过交集终点。常规排班写入已保证营业覆盖，查询仍核验交集，不从“有保护行”推导有可用时段。

## 5. 响应与含义

沿用统一 ApiResponse，data 为 BookingSlotsView：serviceVersion、priceAmount（整数分）、durationMinutes、slots。slots 项为 startAt、endAt，均为带 Z 的 UTC ISO 8601 瞬时，和商家排班的本地 HH:mm 字段有明确区别。

示例仅用于结构说明：虚构价格 3000 分、时长 30 分钟，2026-10-22 校园时间 09:00～10:00，且查询时提前条件满足：

```json
{
  "serviceVersion": "2",
  "priceAmount": 3000,
  "durationMinutes": 30,
  "slots": [
    {"startAt": "2026-10-22T01:00:00.000Z", "endAt": "2026-10-22T01:30:00.000Z"},
    {"startAt": "2026-10-22T01:15:00.000Z", "endAt": "2026-10-22T01:45:00.000Z"},
    {"startAt": "2026-10-22T01:30:00.000Z", "endAt": "2026-10-22T02:00:00.000Z"}
  ]
}
```

slots=[] 时仍返回该有效服务在同一快照中的版本、价格和时长，不伪造“不可用价格”。本轮不额外增加状态或可用性标志字段；文档必须明确候选尚未纳入订单占用。返回不预留人员/时间，不冻结价格；未来下单仍须重新读取配置、核对版本与金额并验证占用。

## 6. 实现与完成标准

复用现有 merchant 分层、注解 SQL、统一公开资格、排班和营业时间，不新增依赖、缓存、XML、模块或迁移。查询采用只读 RR，同一响应内的资格、服务版本/价格/时长、绑定、营业时间和排班来自一致快照；不加写锁、不创建日期保护行、不修改任何版本。候选生成逻辑按时间计算独立验证，不提前抽象“永远返回空”的占用服务。

本次验收标准：

1. 实现一个精确匿名 GET，运行版 32 → 33 个操作，完整规划仍 62 个，剩余 29 个待开发；订单及其他方法/路径继续受现有边界保护。
2. 验证必填/非法参数、统一资格、跨店、服务上下架、人员启停与绑定、PRINT、停业及空结果，包含资格失败优先于停业空结果。
3. 注入 Clock 验证上海日期、今天/第 6 天/窗口外、午夜、恰好 2 小时与相差 1 毫秒、15 分钟取整、升序去重、完整时长、相邻边界、午休/断档、无排班和当前关门但未来有候选。
4. 真实 MySQL 验证 UTC 往返、资格与配置/排班并发变更的一致快照，以及查询不创建保护行、不写配置。不得将其称为真实订单占用或抢位验证。
5. 同步注解、实际运行 OpenAPI、完整规划、阶段范围及 Swagger / Apifox 点击指南。实际执行结果见[验收指南](booking-slots.md)，不能把配置候选测试当作订单占用验证。

人工验收：准备已批准理发店并打开手动营业开关 → 上架 30 分钟服务 → 启用并绑定人员 → 配置目标星期营业时间 → 排明天 09:00～10:00 → 清除 Swagger 授权、填写实际 ID 和明天日期 → 检查三个 UTC 候选；关闭营业开关后为空，服务下架/人员停用/解绑后为 404。整周营业时间保存须保留其他已排班日期的覆盖，不能误清空已有计划。
