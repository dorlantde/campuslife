# 管理员账号列表：已确认方案

- 日期：2026-10-26；状态：用户明确“采用并实现”；落实见[ADR-0045](decisions/0045-admin-account-list.md)，实际验证见[指南](admin-account-list.md)。
- 依据：[接口契约](v1-api-contract.md)、现有AccountView与账号/会话模型、[管理员隐藏评价 ADR-0044](decisions/0044-admin-review-hide.md)。草案已规划列表路径，以下查询范围、分页与权限快照细则已由用户本次确认。

## 1. 推荐范围与完成标准

新增GET `/api/v1/admin/accounts`，仅正常ADMIN与有效会话查询平台业务账号，支持role、status、page、size。这里查询account表中的STUDENT/MERCHANT/ADMIN，不查询MySQL数据库用户。

推荐覆盖所有角色及启用状态，包括当前管理员本人、其他管理员和DISABLED账号；不因账号是否关联店铺、是否有订单或店铺审批状态隐藏记录。无筛选默认查询全部账号，不默认只查学生或只查ACTIVE。

运行接口60→61，完整规划仍62，已实现61、待开发1（账号停用/恢复）。沿admin模块实际增加Controller、只读服务、查询Mapper及AdminAccountPage，复用AccountView；无新表、迁移、依赖或基础设施，仍V1～V14/22张业务表。

完成标准：管理员可以按角色和状态分页查看必要账号资料；权限与查询结果在单个响应内一致；响应和SQL投影均不含密码摘要或会话；真实MySQL验证并发快照及权限，注解、两份OpenAPI和Swagger/Apifox点击指南同步。

本轮不实现停用/恢复、角色修改、账号创建/删除、密码重置、账号详情、关键词搜索、批量导出或会话管理。管理员仍只通过受控初始化创建；后续状态写入、自操作和最后一个管理员保护另行定稿。

## 2. 筛选、分页与顺序

- role可省略；传入时仅接受精确大写STUDENT、MERCHANT、ADMIN。
- status可省略；传入时仅接受精确大写ACTIVE、DISABLED。
- role/status组合为交集；空串、空白、大小写变化或未知枚举400 VALIDATION_FAILED，不静默当作无筛选。
- page默认1，范围1～2147483647；size默认20，范围1～100。沿现有公开目录的十进制字符串解析：只接受数字，不接受空串、空白、正负号、小数、指数或溢出；分页参数前导零允许，例如page=0001表示1。仅省略参数使用默认值。
- 按created_at DESC、id DESC排列，保证同毫秒记录顺序稳定。offset使用long，避免最大页码乘size溢出。

先完成合法管理员请求的参数校验，再进行账号count/page查询。合法组合没有命中时200空页，total=0、totalPages=0；超出末页items=[]但保留真实total/totalPages，不返回404。

不加入关键词、店铺或订单筛选，不改变原有商家申请和订单列表接口的规则。

## 3. 返回字段与隐私

返回AdminAccountPage：items、page、size、total、totalPages。每条严格复用AccountView六字段：

| 字段 | 含义 |
|---|---|
| id | 平台业务账号ID，十进制字符串 |
| username | 归一化后的登录用户名 |
| nickname | 当前昵称 |
| role | STUDENT / MERCHANT / ADMIN |
| status | ACTIVE / DISABLED |
| version | 当前账号版本，十进制字符串，供后续状态修改使用 |

分页统计使用long；ID及版本保持字符串，避免客户端精度丢失。版本是读取时的值，不代表未来修改一定成功；后续写接口仍须重新校验。

列表SQL明确投影这六列，不使用SELECT *或加载带password_hash的AccountEntity再整体序列化。不返回密码/摘要、JWT、jti、会话数量或到期时间、文件信息、联系方式、店铺/订单明细；不增加创建时间响应字段。身份校验只读取已有会话查询需要的账号与会话字段，不读取密码摘要。

## 4. 权限、事务与一致性

仅当前ACTIVE/ADMIN及有效会话。除既有HTTP鉴权外，在本次只读事务内普通读当前账号/会话，复核角色、状态、撤销及到期；不能只相信token中的旧身份。未登录、无效/撤销/过期会话沿原401，非管理员或停用账号403；格式错误400。暂时数据库故障沿现有503 SERVICE_TEMPORARILY_UNAVAILABLE，不把故障伪装成空列表；其他内部异常沿500。

推荐短只读RR事务，身份/会话、相同筛选的count与page处于同一数据库快照。权限不合格先拒绝，返回前再次核对会话到期时间；不用业务行锁，不等待目标账号X锁，不写账号版本、撤销会话或修改任何业务数据。

快照建立后并发注册、新增账号、修改昵称/角色/状态或撤销会话，不改变本次已建立的数据库快照；下一请求读取新事实并重新判断权限。会话到期仍以返回前服务器Clock校验。该边界适用于本次读取，不承诺已停用管理员的在途读取会被强行中断。

count与page同条件、同一响应一致；不同HTTP请求/不同页不保证永久同快照。分页期间新增或变化可以移动后续页，本轮不增加游标或持久快照。使用直接count与投影分页，不逐条查询密码、会话或关联业务，无磁盘IO、缓存、消息或事务外补查；不预先增加索引或宣称未经测量的性能提升。

## 5. 验收范围

1. Swagger/Apifox用既有受控ADMIN登录，默认查询、角色/状态交集、分页与空页，确认本人及其他管理员可见。学生注册、商家申请和受控管理员样本涵盖三种角色；停用样本在独立测试库构造，不因此宣称状态修改HTTP接口已实现。
2. 未登录、学生/商家、无效token、停用管理员、角色已变化、会话撤销/到期；确认事务内快照资格复核，返回前到期拒绝。
3. 大小写/空白/非法枚举，缺省/空串/前导零/正负号/小数/指数/溢出、page最大值、size边界、long offset；同毫秒ID倒序、多页与越界空items但保留total。
4. 严格六字段，不返回摘要/会话/联系方式；账号ID和version为字符串，包含大于JavaScript安全整数的值。读取不修改任何账号/会话或业务事实。
5. 真实MySQL并发新增账号、修改昵称/角色/状态，资格/count/items保持同一RR快照，下一请求反映变更；并发撤销管理员会话或改变管理员资格沿已说明的快照边界。持账号X锁时普通读可完成，不获取业务写锁。
6. 注入count/page故障验证503或原内部错误，无伪造空页；运行61、完整62/61/1、OpenAPI引用/模型/分组、既有账号认证及管理员功能回归、可执行包启动检查。

只使用独立临时MySQL及自有测试文件根，不修改用户现有服务数据或本机启动密钥。通过后记录实际命令、测试数量与点击指南；本方案不是实现完成或测试通过记录。

本次需确认的是全角色/状态可见范围、六字段资料、筛选分页及权限快照边界。已按ADR-0045落实；账号停用/恢复另行推进。
