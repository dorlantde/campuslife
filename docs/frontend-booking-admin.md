## 预约点击流程

1. 商家先按[经营配置指南](frontend-merchant.md)完成服务、启用人员/绑定、营业时间和按日排班。公开人员不保证有空位；当前休息也不等于未来营业日不能预约。
2. 学生从服务卡点“预约理发”，选择人员和**上海日期**，再点“查询预约时段”。校园今天至第6天、至少提前2小时、15分钟起点网格均由后端校验；候选已排除真实占用，查询不预留资源。
3. 核对本次价格、时长、服务版本，选择返回的时段，可填备注，再“确认创建待支付预约”。客户端直接提交候选原UTC值，不用本机时区重造时间，不提交结束时间或人员版本。
4. 成功显示订单编号，再“查看预约订单”。模拟支付确认冻结金额后，商家到本店订单接单；按钮不代表服务端一定允许，所有动作最终仍在后端复核。
5. 同一时段已被占用，旧候选创建会显示`BOOKING_CONFLICT`；清除已核对的旧恢复记录后，重新查询选择。版本/价格变化显示原/当前信息，重新核对后明确提交，不自动接受新价格。
6. 学生可按状态取消：未付直接关闭；已付待接单全额模拟退款；已接单距开始至少1小时可取消，等于允许。商家已接单但尚未到预约开始，可填原因无法履约取消，不受学生1小时限制。
7. **开始/完成留到真实时段操作。** 商家在`startAt≤当前时间<endAt`时刷新详情，才显示“开始服务”；服务中可“完成服务”，允许立即完成，原区间仍保留CONSUMED。学生完成且已付后可评价，一单一次。界面不调时钟、提前开始或新增测试后门。

所有时间显示上海时区。按钮以本机时间和最近读取作提示，不自动轮询推进状态；到时请刷新，系统锁后时间为最终依据。GET不自动关单退款；到期限的支付/接单409可能已经先提交关闭，需看重读结果。

预约恢复与打印共用已验证的客户端机制，但使用**两个独立存储键、操作名和冻结正文**。创建前保存原幂等键，网络不确定时只手动重放原提交，刷新后可恢复；成功备注不会再当作未提交草稿拦截跳转。明确清除恢复记录不取消服务端订单。退出/改密前提示未确认记录，失效或换账号清除两类记录，不自动跨账号重放。详情见[打印恢复说明](frontend-print.md)。

## 管理员核实订单异常

没有全平台订单列表接口，因此只提供按ID读取。核对冻结金额、预约/打印明细、阶段时间和读取版本；填写1～300码点原因，勾选已核实双方，再“确认核实退款关闭”。仅已付待接单、已接单、服务中可处理，已完成不能退款。

提交保留**读取时的订单版本字符串**，不取新版本自动重试。发生版本冲突时表单锁定，须明确重新读取、重新填写原因并核实；读取会清除旧草稿。编号输入改变后也必须重读。网络不确定先重读事实，不把请求中断等同于回滚。

BOOKING未开始关闭释放原占用，开始后保留原区间；PRINT转ABORTED，保留已发生的开始/待取件时间，文件继续按全部引用计算期限。新退款仍受原模拟资金开关保护。管理员仅看冻结文件元数据，无PDF下载入口或默认内容权限。

## 账号与评价

账号页只返回既有六字段，默认20条，按角色/状态交集查询。选中时冻结目标账号版本，禁止修改本人，包含同状态操作。勾选影响确认后变更；冲突需重新查询，不能自动覆盖别人刚做的处理。停用或恢复的实际变更撤销旧会话，恢复不复活旧token，须重新登录；不会自动取消或退款旧订单。

评价处理没有全部列表或详情GET。由公开页带入时，URL只带商家ID/评价ID/页码，页面重新读取真实公开页取得摘要，不信任URL中的评价文字。未找到内容或手输ID时明确“仅按ID核实”，不合成摘要。

填写原因并确认影响后隐藏；第一次提交冻结评价ID和原原因。结果不确定可手动重试原请求，不自动换目标/原因；需要新的处理先明确清除本页草稿。隐藏不编辑、删除或恢复评价；公开统计随后排除，本人仍可读，订单reviewed保持且不能重发。
