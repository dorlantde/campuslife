日期：2026-11-02。状态：**用户已采用，A/B/C已验证，M04收口。** [B报告](reports/s3-file-chain-2026-11-02.md)/[指南](s3-file-storage.md)：918项不同相关检查分轮通过，文件业务已支持LOCAL/S3及V24，75操作/32表、默认LOCAL。SDK进入生产包，S3后端默认关闭；未迁移项目库或实际文件。下文保留原提案内容，其中拟议/未实施措辞是当时阶段记录，当前执行状态以[路线图](roadmap.md)及分批报告为准。前端暂停。 C结果见[110项恢复验收](reports/s3-recovery-2026-11-02.md)及[指南](s3-recovery.md)：隔离恢复/迁移通过，真实搬迁仍另行授权。

## 1. 推荐与目的

推荐使用**本机单节点SeaweedFS的私有S3接口＋AWS SDK for Java 2.x同步客户端**。新上传按明确配置选择LOCAL或S3，旧文件继续按自身存储定位读取/清理；默认仍LOCAL，S3故障返回原存储503，不自动回落本地另存。学生与商家继续使用原后端受控下载，不给公开对象地址或预签名URL。

业务问题是让打印文件内容与应用本机磁盘解耦，并验证“数据库元数据＋远端对象”之间的失败恢复；不以更换存储声称上传更快、应用可多实例或实现分布式存储。学习产出是S3协议接入、私有访问、IO与事务边界、未知结果补偿、备份恢复和历史兼容，不扩展大文件分片/CDN/直传。

## 4. 保留的业务与存储身份

保持20MiB、1～500页、拒绝加密、两个上传处理槽；原24小时、未结束引用NULL、全部终结后7天；原学生/商家权限、ADMIN无默认内容权限、下载附件/no-store、无Range/直传。公开FileView、原HTTP路径和业务状态保持。新存储不参与资金或订单事件。

`storageKind + storageId + storageKey`组成定位：LOCAL id仍来自原`.storage-id`；S3 id是显式初始化的存储命名空间UUID，映射到固定endpoint/bucket/随机前缀，不能把同一id静默指向另一桶。key仍36字符，实际S3路径由受管前缀与key组装；不写学生姓名、学号、原文件名。不在每行存密钥或可访问URL。

应用配置只接受显式登记的LOCAL根及一个S3命名空间；不接受请求传入endpoint/bucket/key，也不任意注册插件。缺失或不匹配的存量定位返回503并报警，不尝试其它后端。初始化使用独立操作身份创建桶/标识，应用只获受管对象前缀的必要读写删除与标识读取权限；桶管理、其它前缀和匿名读取必须实际拒绝。原根和新命名空间不得复用同一个UUID。

S3关闭只表示不启用该后端；若已有S3记录，关闭后这些文件仍明确503，不能把关闭开关当作数据回滚。将“新上传目标”改回LOCAL，可停止新增S3文件，已存在S3记录仍需配置其后端。无S3记录且默认LOCAL时，不创建SDK连接/访问S3。配置缺失/冲突应早失败；远端临时不可达不阻止LOCAL旧文件和其它业务启动，S3操作拒绝，恢复时核对命名空间。

本机存储接口仅绑定回环；容器其它管理/文件入口不映射给宿主或浏览器，内部网络与凭据隔离需探针核对。后续跨主机部署另行配置TLS，不把本机HTTP开发设置当作公网方案。无桶自动生命周期删除、版本控制或对象锁，避免绕过DB引用保护及引入删除标记语义。

## 5. 上传、下载、删除的事务与恢复

### 上传

1. 在原两个处理槽内完成本地流式限额、SHA256和PDF校验，不新增公共队列。
2. 取得与下载/清理/首次打印下单共用的实例互斥，短RC原锁序下保存UPLOADING，冻结kind/id/key/hash/大小，沿用30分钟发布期限。
3. 在事务外执行单次对象PUT（SDK可有有界重试；同一占位的key/字节固定不变），再完整GET计算SHA256/大小，与暂存结果比对后才能发布。20MiB以内回读的额外带宽/耗时明确计成本；不以HEAD长度或ETag冒充内容验证。
4. 短RC复核身份、会话、UPLOADING/版本、定位及期限，沿原规则发布AVAILABLE；响应丢失依然可能已成功，重复上传仍为新文件，不新增上传幂等业务规则。
5. 失败时只允许按当前DB事实处理未发布占位；未知publish提交先读回，AVAILABLE绝不能被失败补偿删掉。对象PUT结果未知也不能直接认为对象不存在或提前丢失定位。

### 下载与下单

下载仍先授权、等实例互斥、再新RR授权；网络IO不在事务中。对象流长度及首读成功前不准备PDF响应；未提交失败返回原503，已提交失败由容器中断，不拼接JSON。商家取消退款不等待网络传输，获准的本次传输可完成，下一次请求重判；清理tryLock跳过。

首次打印创建在同一互斥下做事务外存储检查，随后短事务核对完整定位及原引用/有效期，仍不能锁行等S3；报价、支付、退款、取件、已有创建键重放继续只依赖其原有元数据/事实，不附加远端IO或反向账号锁。所有入口必须使用同一互斥组件，不能只替换上传下载后漏掉`PrintOrderService`。

### 清理与晚到写入

原短事务标DELETING→事务外精确key删除→短事务按版本标DELETED继续使用；若DELETE响应丢失，重试同一不可复用key，不清空前缀。无未终结引用才允许进入删除；拒绝认证/未知状态不伪装成“对象不存在”。

**新增的必要补偿：未知PUT可能在删除成功之后才到达存储端。** 30分钟占位超时、SDK超时或一次HEAD=404都不能证明以后不再出现对象。保留已有DELETED行作为可追踪墓碑，对受管S3命名空间内的DELETED key按id游标循环复核/精确删除；检查状态、定位和版本，key永不复用。未知PUT只会落到有占位的key，不能创建没有数据库来源的对象；墓碑不因30分钟过去就自动停止核对。缺失对象为成功，失败保留下一轮，重启从持久行恢复；不新增墓碑表，不定时扫描并删除整桶未知文件。

清理与墓碑复核使用组件私有单工作线程/无任务积压，共享定时回调仅唤醒，防止S3故障占住订单到期调度。建议每60秒、每类最多100条、轮内1秒继续预算，单次已开始的IO可收尾；游标循环及两类轮转避免已删墓碑长期挤占新到期文件。拟议V24按实际查询增加`(storage_id,status,id)`索引支撑墓碑分页。临时文件仍只清本地受控目录，启动和运行扫描不递归清空用户根。累计墓碑意味着随规模增加有巡检成本，本项目不承诺固定物理删除延迟。

建议SDK初值：连接/连接获取2秒、socket读空闲5秒、API单次尝试15秒/调用30秒、标准策略总尝试最多2次、连接池4；A记录最终可用参数，B验证异常不耗尽共享调度。API超时/中断不保证服务端取消PUT；下载流与客户端慢速接收也不能仅靠API超时认定有30秒完整传输上限。[官方超时分层](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/timeouts.html)。本提案不改变现有慢客户端传输语义，不声称应用整体有硬退出SLA。

## 6. 历史文件：默认共存，实际搬迁另行授权

推荐本阶段**不自动迁移真实文件**，已有LOCAL记录和根继续可读、下单及清理，新S3文件走另一后端。应用升级不复制、不重写旧定位，不主动访问未配置的根；只因新上传改成S3而撤掉旧根会造成旧单不可用。所有旧记录结束也不自动授权删除旧目录或备份。

M04.2-C提供隔离数据上的迁移预演与只读计划格式，生产Apply不包含在本轮或本方案采用的自动执行授权中。将来实际迁移须先给用户可审阅清单、备份和具体目标，再明确批准。推荐离线维护窗口，暂不设计在线双写/边读边迁移：

1. 停止所有能访问源库/根的应用、清理和文件维护入口，确认已无活动传输/写入；新建或已批准的专用目标命名空间。不能只停Web页面或以跨实例不共享的ReentrantLock当作停机证明。
2. 一致性备份MySQL和原完整本地根（含`.storage-id`），导出指定AVAILABLE文件计划：fileId、源/目标定位、版本、长度/hash/期限；清单不含密码/token。UPLOADING/DELETING先恢复收敛，缺失/校验异常只列报告，不能改变状态掩盖缺文件。
3. 按计划逐文件复制到固定目标key，完整GET校验大小及SHA256；不删除源。目标IO与DB事务分开，记录每文件处理状态，未知PUT/孤立目标按计划恢复核对。
4. 在短事务中按原kind/id/key/version/status条件切换定位、version+1，期限/订单引用/订单版本不变。结果未知先读事实；不能在未知提交时盲删目标。条件不符停止该项，禁止强行覆盖；没有已切换事实的目标也只能由已知迁移清单精确补偿。
5. 离线比对清单、元数据与源/目标hash，在隔离恢复环境验证旧订单下载及引用保护后再恢复应用。失败可在停机状态下按清单条件回指仍保留的源；一旦恢复写入，不能直接还原整库覆盖新业务。源目录删除、线上批量执行及迁移工具新规则均需独立授权，不作为本阶段必须做的业务扩展。

这种保守选择保留了一段双存储运维成本，换取旧文件不因切换受影响。单应用实例边界保持；引入S3并没有使实例互斥、上传槽和文件扫描变成分布式协调。
